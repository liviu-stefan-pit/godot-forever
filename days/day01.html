Before you start

  • A Windows 10 or 11 64-bit PC with a mouse that has a middle button (the wheel click) and about 1 GB of free disk space. A laptop trackpad works too, with one setting change we cover in section 4.
  • An internet connection for the download (about 100 MB in total). After that, the whole course works offline except the optional Asset Library and the starter downloads we point out.
  • A GPU that supports Vulkan 1.2 is recommended for the Forward+ renderer (anything from the last ~8 years). If the editor refuses to start a Forward+ project later, create projects with Compatibility instead (we explain renderers in section 2).
  • File Explorer open, and PowerShell available (Start menu, type PowerShell). We only use PowerShell for two optional commands today.
  • Two folders will be created today: C:\Godot\ (the editor program) and C:\GodotProjects\ (all your projects, one folder per project). Keep projects out of OneDrive/Dropbox-synced folders: sync clients fight with Godot's cache folder.
Which Godot version?

The course targets the latest 4.x stable. The documentation this course is checked against describes Godot 4.7 (June 2026) as the newest stable release and 4.8 as in development. Everything we use works from 4.4 onward; where a button or menu was renamed between versions we say so in a callout like this one. Pick one version today and keep it until Day 30: projects are upgraded one-way and a mid-course upgrade is a distraction.

Concepts you need first

You code well; what you lack is Godot's vocabulary. Read this once now (15 minutes including the two docs pages); Day 2 deepens each row of the table with code.

Godot's mental model in one table

Godot termWhat it isClosest thing you know
NodeThe smallest building block. Every node has a name, properties, and per-frame callbacks, and can have child nodes. A Sprite2D draws a texture, a Timer counts time, a Camera2D frames the view.Unity: GameObject + one built-in component. Unreal: a component. Web: a DOM element.
SceneA saved tree of nodes (a .tscn file). Once saved, it behaves like a new node type you can instance anywhere. A scene can be a player, a bullet, a menu, or a whole level.Unity: Prefab and Scene. Unreal: Blueprint class and Level. Web: a component.
Scene treeThe live tree of every node in the running game. Your main scene is its trunk; instanced scenes are branches.The DOM / the hierarchy panel at runtime.
ScriptA GDScript file attached to a node that extends that node's class. It is not a separate component: the node is the class.Unity: MonoBehaviour (but inheritance instead of GetComponent). Unreal: a Blueprint's event graph.
SignalA named event a node emits ("button pressed", "timer finished", "body entered"). Other nodes connect functions to it. This is how nodes talk without hard references.C# events / delegates, UnityEvent, Unreal dynamic delegates, DOM events.
ResourceA data container saved to disk (.tres) or in a scene: textures, materials, shapes, your own data classes. Loaded once and shared.ScriptableObject, Data Asset, a typed JSON file.
AutoloadA script or scene that Godot adds to the scene tree before everything else and keeps alive across scene changes.A singleton / game instance / subsystem.
The one idea to carry into every day

Instead of designing class hierarchies up front, design scenes: one scene per thing the player sees (player, enemy, bullet, HUD, level), then instance them into each other. Godot was built around this. Read the short official pages Overview of Godot's key concepts and Design framework now; they take about ten minutes.

Practical facts about the engine

  • The editor is a Godot game. Its docks and buttons are built from Godot's own UI nodes. That is why Godot is a single small executable.
  • A project is just a folder containing a text file named project.godot. Scenes, scripts and resources are text files too (friendly to Git). Binary caches live in a hidden folder that Godot regenerates.
  • No installer, no launcher account, no license key. You unzip one .exe and run it. Godot is MIT licensed; you will ship its license text with your games in Part 2.
  • Export templates (the prebuilt runtimes used to package your game for Windows, Android, ...) are a separate download. You get them on Day 4, when you export your first game. You do not need them to run a game from the editor.
  • GDScript only. You will be using the standard build, not the .NET build, and no C# anywhere in this course.

1. Install Godot (about 25 minutes)

External resource (not in the Godot docs)

Downloading is done on the official site, godotengine.org. The site layout and file names change over time. If a button below is named differently, look for the equivalent: Download > Windows > the standard (non-.NET) stable build. Verify on the official page; steps change.

Click "Mark done" on a step to track where you stopped.

  1. Open the download page. In your browser go to godotengine.org and click Download in the top menu. Choose Windows if the page does not already detect it.
  2. Pick the right build. The page offers two big buttons: the standard Godot Engine build and a .NET build (for C#). Click the standard one, the one that does not say .NET. You get a file named like Godot_v4.x-stable_win64.exe.zip (with your version in place of 4.x). Make sure the word stable is in the name, not beta, rc or dev. If you accidentally download a mono or dotnet file, delete it and download again.
  3. Unblock the zip (optional but saves trouble). In File Explorer open Downloads, right-click the zip, choose Properties. At the bottom of the General tab, if you see a Unblock check box, tick it and click OK. (This tells Windows you trust the file and reduces the warnings in step 6.)
  4. Create the permanent folder. In File Explorer open This PC > Local Disk (C:). Right-click an empty area, choose New > Folder, type Godot and press Enter. The folder is now C:\Godot\. Choose a folder you will never move or delete: your shortcuts and taskbar pin point into it.
  5. Extract the zip. Right-click the downloaded zip, choose Extract All…, click Browse…, select C:\Godot, click Select Folder, then Extract. (On Windows 11 the item may be under Show more options. If the zip contains a sub-folder, open it and move the files up so the .exe files sit directly in C:\Godot\.) Do not run Godot from inside the zip or from Downloads.

    You now have two programs:

    C:\Godot\Godot_v4.x-stable_win64.exe           the editor (double-click this one)
C:\Godot\Godot_v4.x-stable_win64_console.exe   same editor, plus a black console window that shows logs

    Use the first one every day. The _console variant is for the rare day the editor will not start: the console window prints the reason.

  6. First launch and SmartScreen. Double-click Godot_v4.x-stable_win64.exe. Windows may show a blue "Windows protected your PC" box. Click More info, then Run anyway. Windows shows this for programs it has not seen many times; you only see it on the first launch of each new version. If you get a Windows Defender Firewall prompt, you can click Cancel: the editor does not need incoming connections for anything in this course. If your antivirus quarantines the file, restore it and add C:\Godot to the exclusions (downloads from godotengine.org are safe).
  7. Look at what opened. A window titled Godot Engine - Project Manager appears with an empty project list. A dialog with some welcome text may pop up on the very first launch; read it, then close it. Do not create anything yet.
  8. Pin it. The Godot icon is now on your taskbar. Right-click it and choose Pin to taskbar. Optionally also create a desktop shortcut: right-click the .exe in File Explorer, Show more options > Send to > Desktop (create shortcut).
  9. Optional: the interface language. In the Project Manager click Settings (top-right corner). If your language is not English, set the language to English: every menu and button name in this course is the English one. While you are here, notice the entries for theme, display scale, network mode and directory naming convention; the official page Using the Project Manager describes them. Close the Settings window.

The Project Manager window is open, the Godot icon is pinned to your taskbar, and C:\Godot\ contains the two .exe files. If a window says "No suitable GPU" or the program closes immediately, start the _console.exe version and read the last lines it prints; the usual fix is to create projects with the Compatibility renderer (section 2) and update your graphics driver.

What "no installer" means in practice
  • Portable editor. Godot writes its settings under %APPDATA%\Godot\ (paste that into the File Explorer address bar to look). If you create an empty file named _sc_ next to the .exe, Godot switches to self-contained mode and keeps everything in an editor_data folder beside the program instead. Details: File paths in Godot projects. You do not need this for the course.
  • Updating means downloading a new zip. Put it into its own folder (for example C:\Godot\4.8\) so the old version keeps working for old projects.
  • Export templates arrive on Day 4 through Editor > Manage Export Templates…. Nothing to do today.
External resource: the Steam version (alternative)

Godot is also published on Steam (search "Godot Engine" in the Steam store; the official docs link app 404790). It auto-updates through Steam and uses self-contained mode by default, so its settings are kept next to the program instead of in %APPDATA%. Everything in this course works the same, but the Steam copy may be one version behind the website download, and you must not let it auto-update mid-course. We recommend the plain zip for this course because you control the version. Verify on the official page; steps change.

2. The Project Manager and your sandbox project (about 20 minutes)

The Project Manager is the window you saw in step 7. It lists your projects, and creates or imports them. Each project is a separate folder with its own settings. From Day 3 you will create one project per game; today you create g00-sandbox, a throwaway project where you practice and where Day 2's exercises also live.

The renderer choice, explained

When you create a project you must choose how Godot draws. You can change it later (click the renderer name at the top-right of the editor), but 3D scenes may need lighting tweaks after a switch, so it is worth choosing deliberately. Source: Overview of renderers.

RendererChoose it whenTrade-offIn this course
Forward+Desktop games, especially 3D; you want every rendering feature (volumetric fog, SDFGI, SSR...).Needs a Vulkan / Direct3D 12 / Metal capable GPU. Highest base cost. Poorly optimised for phones.Sandbox and Part 1 games (Days 3-13). Default choice.
MobileNewer phones and tablets, or desktop where you still want modern features at lower cost.Fewer features than Forward+ (no volumetric fog, SSR, SDFGI...). Same GPU requirements.Part 2 (Android-targeted 2D games). Explained again on Day 15.
CompatibilityOld or low-end hardware, web exports, or when Vulkan fails to start. Good enough for most 2D games.Uses OpenGL; fewest features; new features arrive last.Your fallback if Forward+ does not run on your PC.
Why does a 2D game even care?

2D and 3D both go through the chosen renderer. Forward+ draws 2D perfectly well, but the official docs point out that Compatibility is usually enough for 2D and runs on more devices. Part 1 stays on Forward+ so that a single project can mix 2D and 3D without surprises.

Create the sandbox

  1. Tour the Project Manager first. Look at the window: the two tabs at the top are Projects (your projects; the name may read Local Projects in some versions) and Asset Library (community demos and templates). The buttons are on the top-left and right of the project list: Create, Import and others such as Scan, Remove and Manage Tags. There is also a search/filter box, and the Settings button at the top-right.
  2. Peek at the Asset Library tab. Click Asset Library. It says it needs to go online and shows a Go Online button. For privacy reasons Godot makes no network connection until you click it. You do not need it today; if you click it, Godot will also notify you about new Godot versions. You can switch back to Offline in Settings > Network Mode. Click back to the Projects tab.
  3. Open the Create dialog. Click Create (top-left). A Create New Project window opens.
  4. Name the project. In Project Name type g00-sandbox.
  5. Make the folder yourself. Next to Project Path click Browse. A Godot file browser opens (not the Windows one). In the path field at the top, pick drive C: from the drive drop-down (if there is one) and click on C:\. Click the new folder button (the last icon at the right end of the top row), type GodotProjects, press Enter, and open that folder by double-clicking it. Click the new-folder button again, type g00-sandbox, press Enter, and double-click to enter it. Click Select Current Folder. The path field now shows C:\GodotProjects\g00-sandbox and, because the folder is empty, a green check mark appears at its right end. (There is also a Create Folder option that makes a sub-folder named after the project automatically. We avoid it here so the folder name is exactly what the course uses everywhere.)
  6. Choose the renderer. Under Renderer select Forward+. The description beside it summarises what it does. (If your GPU is old, select Compatibility instead; everything in Days 1-2 works with either.)
  7. Choose Version Control Metadata. In Version Control Metadata choose Git. This does not run Git or require it: it only writes two small text files, .gitignore and .gitattributes, into the project, so a future git init does the right thing (details in section 11).
  8. Create. Click Create at the bottom of the dialog. The window closes and the editor opens after a few seconds. The first time a project opens, a progress bar says it is importing icon.svg.
  9. Return to the Project Manager once, on purpose. In the editor's menu bar choose Project > Quit to Project List (Ctrl+Shift+Q). Back in the Project Manager your project appears in the list with its icon, path and Godot version. Double-click it to open it again. This is how you will start every working session.

The editor is open with the title g00-sandbox and an empty viewport. In File Explorer, C:\GodotProjects\g00-sandbox contains at least project.godot, icon.svg, .gitignore, .gitattributes and a .godot folder (it can be hidden; enable View > Show > Hidden items to see it). If the folder name differs (for example g00_sandbox), you used the Create Folder option together with a naming convention: remove that project from the list and repeat steps 3-9.

Importing a project later

To open someone else's project (or a downloaded starter zip), click Import, select the project.godot file or the folder (you may also pick a zip, which Godot extracts for you) and click Import. A message that the project was last opened in an older Godot version is normal; click OK. If the editor ever crashes repeatedly on a project, the project's drop-down next to Edit offers Edit in recovery mode, which disables tool scripts and plugins.

3. The editor tour: a scavenger hunt (about 35 minutes)

Reading a description of a UI never sticks; hunting for each part does. The diagram below is the default layout as the official docs describe it. Study it for one minute, then do the hunt. Your layout can differ slightly: Godot 4.x lets you move docks and the newest versions offer more dock options, so if something is not exactly where the text says, check Editor > Editor Layouts > Default (step 13).

Now the hunt. Do the steps in order; each one ends with a small proof so you know you really found the thing. Keep the sandbox project open with the empty viewport.

  1. Menu bar. Top-left of the window. Click Scene and read the entries (New Scene, Open Scene, Save Scene...); hover without clicking and notice the shortcuts at the right of each entry. Press Esc. Open Project, Debug, Editor and Help the same way. Proof: write down which menu contains Project Settings… and which contains Editor Settings… (Project and Editor, respectively).
  2. Workspace buttons. Top center. Click 2D, 3D, Script, Game, AssetLib in turn. The big middle area changes; the docks stay. The editor also switches workspace by itself when you select a node (a Node2D opens 2D, a Node3D opens 3D). The keyboard shortcuts for the first ones are Ctrl+F1 (2D), Ctrl+F2 (3D), Ctrl+F3 (Script) and so on; check Editor > Editor Settings > Shortcuts if yours differ. Proof: end on the 2D workspace.
  3. Play buttons. Top-right. Hover each icon for one second to read its tooltip and shortcut: Run Project (F5), Pause, Stop (F8), Run Current Scene (F6), Run Specific Scene. The Movie Maker Mode toggle is next to them (you will not use it in this course). At the far right is a drop-down with the renderer name (Forward+): that is the switch mentioned in section 2. Proof: the tooltip of Run Current Scene names the shortcut F6, and the tooltip of Run Project names F5.
  4. Scene tabs. Directly under the workspace buttons. Right now the tab bar may be empty. The + at its end creates a new empty scene. At the far right end of the tab bar is the distraction-free mode toggle (hover to read its name). Do not click it yet.
  5. Scene dock. Top-left. With no scene open it offers quick root-node choices: 2D Scene (a Node2D root), 3D Scene (a Node3D root), User Interface (a Control root) and Other Node (pick any node type). Once a scene has a root, the buttons at the top of the dock are Add Child Node (a +, shortcut Ctrl+A) and the chain-link button Instantiate Child Scene, plus a filter box. Proof: click 2D Scene. A node called Node2D appears in the dock and the viewport switches to 2D. Leave it for the next steps (you can undo later with Ctrl+Z or close the tab).
  6. FileSystem dock. Bottom-left. It shows res://, the root of your project, containing icon.svg. Double-click a folder to open it; right-click a file to see the context menu; use the filter box at the top to find files by name. (We use it to make folders, scenes and scripts all day.) Proof: click icon.svg; the Inspector area to the right changes to show the Import tab for the file.
  7. Viewport and its toolbar. Center. Click Node2D in the Scene dock. Above the canvas is the toolbar: select, move, rotate, scale, snapping and a View menu. The toolbar changes with context: in 2D it differs from 3D, and extra buttons appear for some selected nodes. Proof: hover the first four tools; their tooltips show Q, W, E, S in 2D.
  8. Inspector. Right side. With Node2D selected it lists the node's properties grouped in foldable sections (Transform, CanvasItem ...). Hover the Position property for a second: a tooltip shows what it does and its name in code (position). That Title Case ↔ snake_case relationship holds for every property. At the top of the Inspector there are history arrows (< >), a filter box and a tool menu. Proof: type rot into the filter box; only Rotation related properties remain. Clear the box.
  9. Node tab (Signals and Groups). Next to the Inspector's tab, find the tab named Node. Inside it are two sub-tabs, Signals and Groups. Signals lists what the selected node can emit, Groups lets you tag nodes. We use both on Day 2. Proof: with Node2D selected, open Signals: the list has entries such as visibility_changed and ready. Switch back to Inspector.
    Version note: Node tab vs Signals/Groups docks

    In Godot 4.0-4.x the Node tab sits next to the Inspector and holds Signals and Groups. The official docs for the newest versions call them the Signals dock and the Groups dock (the old combined Node dock is deprecated in the editor feature profiles), so on your version they may be two separate tabs beside the Inspector with those exact names. Same function, same steps: wherever this course says "Node tab > Signals", open the Signals tab.

  10. Bottom panel. The strip at the very bottom. Click Output: a panel slides up (this is where print() text and errors appear). Click Debugger, then Audio (the audio bus mixer), then Animation or Shader Editor if they are listed. Other tabs (SpriteFrames, TileSet, ...) appear only when you select a node that needs them. Click the active tab again to fold the panel. Drag the panel's top edge to change its height. Panels are folded by default because they take a lot of space. Proof: the panel is folded again with nothing selected.
  11. Resize and move a dock. Drag the vertical border between the Viewport and the Inspector to the left: the Inspector gets wider. Drag the horizontal border between Scene and FileSystem dock: heights change. To move a dock, click the three vertical dots icon at the top of a dock (for the FileSystem dock, next to its title), and pick a new location from the menu that appears (for example the right side). The same menu has Make Floating, which turns the dock into its own window; to put it back, close that window with its × (or press Alt+F4 while it is focused). If you cannot find a dock that disappeared, Editor > Editor Docks lists docks (for example Inspector) that can be shown again. Proof: move the FileSystem dock to the right side, then continue.
  12. Distraction-free mode. Click the distraction-free toggle at the far right of the scene tabs bar. All docks and the bottom panel vanish and the viewport fills the window. Click it again to bring everything back. (You will use this when you want maximum room for a big level or a long script.)
  13. Reset the layout. Open Editor > Editor Layouts. The list contains Default (a hardcoded layout that matches a fresh install and cannot be removed), plus Save (store your current arrangement under a name) and Delete. Click Default. The FileSystem dock jumps back to the bottom-left. Proof: your layout matches the diagram again. Layouts are stored in a file named editor_layouts.cfg in the editor settings folder.
  14. Close the empty scene. Our Node2D scene was only practice. Click the small × on its tab. If Godot asks whether to save, click Discard (or the equivalent). Under Editor > Editor Layouts nothing else needs changing.

Without scrolling up, you can name from memory: where Run Current Scene is, which dock lists res://, which dock lists nodes, which panel shows print() output, and how to reset the layout. Quick self-test: close your eyes, picture the screen, say the nine areas out loud (menu bar, workspace buttons, play buttons, Scene dock, FileSystem dock, Viewport, Inspector, Node tab, bottom panel). If one is fuzzy, repeat that step. You have a layout quiz at the end of the day.

4. Editor Settings you must set today (about 10 minutes)

There are two different settings windows in Godot and mixing them up is the most common beginner confusion:

WindowMenu pathApplies toStored in
Editor SettingsEditor > Editor Settings…Godot itself: fonts, theme, code editor behaviour, shortcuts. Shared by all projects.Your user profile (%APPDATA%\Godot\), not in the project.
Project SettingsProject > Project Settings…This game: window size, input actions, autoloads, physics layers, main scene.project.godot inside the project folder.
  1. Open Editor Settings. In the menu bar click Editor > Editor Settings…. A window opens with a category tree on the left, settings on the right, a search box at the top, and tabs such as General and Shortcuts. Hovering any setting's name shows its description.
  2. Find the indentation setting. In the search box type indent. The tree filters to Text Editor > Behavior > Indent (the full path from the class reference is text_editor/behavior/indent/type). If you prefer browsing, click Text Editor in the tree, then Behavior, then expand Indent.
  3. Set Type to Spaces. Click the Type drop-down (currently Tabs) and choose Spaces.
  4. Set Size to 4. Click the number field next to Size, type 4, press Enter. With spaces selected, this is how many spaces one press of Tab (or one automatic indent) inserts.
  5. Optional safety net. Search for convert indent. Tick Convert Indent on Save (text_editor/behavior/files/convert_indent_on_save): when you save a script, Godot converts its indentation to match the setting above. Also tick Trim Trailing Whitespace on Save if you see it (search trailing); it keeps Git diffs clean.
  6. Turn on type hints in code completion. Search type hints. Make sure Add Type Hints (Text Editor > Completion > Add Type Hints) is checked. With it on, Godot adds things like -> void and : int when you accept an autocomplete suggestion, create a script from a template, or connect a signal from the editor. This course writes statically typed GDScript, so you want those hints generated for you.
  7. Make everything readable. Search font size. Main Font Size controls menus and docks, Code Font Size controls the script editor (both under Interface > Editor > Fonts). Try 16 for both on a full-HD monitor; larger if you squint. If the whole interface is too small on a 4K screen, search display scale and set Display Scale (under Interface > Editor > Appearance, named Display Scale in all versions; on older versions it sits directly under Interface > Editor). A restart prompt may appear for the scale; click Save & Restart and reopen the project from the Project Manager.
  8. Pick a theme. Search theme and look at the Interface > Theme entries: a color preset (the setting is named Color Preset in the newest class reference and Preset in older documentation) with choices such as Default, Light and Black (OLED), plus an accent color and contrast. Light is easier outdoors, dark is easier on the eyes at night. Choose whatever you like; screenshots do not exist in this course, so nothing depends on it.
  9. Make the editor speak English. Search editor language and set Editor Language to English if it is not. Every menu name in the course is the English one.
  10. Laptop or trackpad users only. Search emulate. Tick Emulate 3 Button Mouse (lets you pan, zoom and orbit the 3D view without a middle mouse button) and, if your keyboard has no number pad, Emulate Numpad (Editors > 3D). Both are described on the Customizing the interface docs page.
  11. Close the window. Settings are saved immediately when you change them; click Close.
Why spaces and not tabs?

GDScript is indentation-sensitive, and it is an error to mix tabs and spaces in one file ("Mixed use of tabs and spaces for indentation"). The official GDScript style guide actually recommends tabs, and the editor setting's own description says so. This course nevertheless uses 4 spaces in every code listing, because spaces survive copy-paste from a web page and from chat exactly as written. If you leave the editor on Tabs, then pasted code (spaces) plus your own Tab key presses (tabs) will produce that mixed-indentation error again and again. Either use spaces everywhere (the course way) or consistently tabs in your own projects after the course; never both in one file.

Indentation Type is Spaces and Size is 4; Add Type Hints is ticked. You will verify the first one for real in section 8: the script editor's status bar (bottom of the code area) shows whether it is using tabs or spaces.

5. Your first scene, F5 vs F6, and what is on disk (about 25 minutes)

You will build the smallest possible scene (one Label), save it, run it two ways, and then look at what Godot wrote to disk.

  1. Make a folder for today's files. In the FileSystem dock (bottom-left), right-click an empty area (or res://) and choose New > Folder…. Type day01 and click OK. The folder appears under res://. (Godot style: folders and files in snake_case, lowercase. Always create and rename files inside the FileSystem dock, not in File Explorer, so Godot can fix references.)
    Verify: context menu wording

    The FileSystem right-click menu is not spelled out in the official docs. In Godot 4 it has a New sub-menu with Folder…, Scene…, Script…, Resource… and TextFile…; on some versions the sub-menu may be titled Create New. Same items either way.

  2. Create the root node. In the Scene dock (top-left; the editor should have an empty scene after you closed the practice tab; if not, click Scene > New Scene), click Other Node. The Create New Node dialog opens with a long tree of node types and a search box at the top.
  3. Pick Label. Type Label in the search box, click Label in the list (not LinkButton or others), then click Create at the bottom. Three things happen at once: the workspace switches to 2D (a Label is a 2D-space UI node), the node appears in the Scene dock, and its properties appear in the Inspector.
  4. Edit a property. In the Inspector (right), click in the box under Text and type Hello Godot. The text appears in the viewport as you type, near the top-left corner (the node's origin).
  5. Rename the node. Click the node in the Scene dock and press F2. Type Hello and press Enter. (Node names are PascalCase. Names matter: code addresses nodes by name.)
  6. Move it with the move tool. In the viewport toolbar click the Move Mode tool (or press W). Click and drag the label towards the middle of the indigo/purple rectangle in the viewport: that rectangle is the game's window. Press Q to go back to the select tool. Notice Position in the Inspector's Transform section changed.
  7. Run the current scene. Press F6 (Run Current Scene, top-right). Godot refuses to run an unsaved scene and opens a Save Scene As dialog. Version note: .uid files and uid:// paths

From Godot 4.4, scripts and many resources have a stable unique ID stored in a sibling .uid file, and the editor may show references as uid://... in places where older versions only showed res:// paths. 6. The 2D workspace, hands-on (about 25 minutes)

Almost every game in Part 1 and all of Part 2 live in the 2D workspace, so we practice its tools on the one texture every project has: icon.svg (a 128 × 128 Godot logo).

  1. New 2D scene. Click Scene > New Scene, then in the Scene dock click 2D Scene. A root Node2D appears. Press F2, type Playground2D, press Enter. Press Ctrl+S and save as res://day01/playground_2d.tscn.
  2. Add a sprite by dragging. In the FileSystem dock, drag icon.svg into the viewport, roughly into the middle of the indigo rectangle, and drop it. A Sprite2D node named icon appears as a child of the root (a dropped file becomes a child when the root is selected). Rename it Icon with F2. Look in the Inspector at its Texture property: it now holds icon.svg. This is exactly what the drag did for you; you can also drag the file into that slot.
  3. Put it in the exact center of the window. With Icon selected, open the Inspector's Transform section (click its title to unfold it). Set Position to x = 576, y = 324. (Click a number and type, press Tab or Enter to confirm. You can also drag a number sideways to scrub it.) That is half of the default 1152 × 648 game window.
  4. Use the four tools. In the toolbar (or with the keys) try each on the icon: Select Mode (Q: drag to move, hold Ctrl to rotate, drag the red circles to scale), Move Mode (W: drag the green or red arrow to move along one axis only), Rotate Mode (E) and Scale Mode (S). After each, look at the Inspector's Position, Rotation and Scale. Press Ctrl+Z repeatedly to undo, or click the circular revert arrow beside any changed property to restore it to its default.
  5. Learn the 2D coordinate system. Two long lines cross the viewport: red is the X axis, green is the Y axis; where they cross is the origin (0, 0), the top-left corner of the indigo rectangle. Set Position y to 0, then 100, then -100. Positive X is to the right and positive Y points DOWN. (This is the opposite of school graph paper and the number-one source of "my character jumps the wrong way" bugs. "Up" is Vector2.UP, which is (0, -1).) Set Position back to (576, 324).
  6. Rotation: editor degrees, code radians. Type 45 into Rotation. The Inspector works in degrees. In code, the property rotation is in radians (PI is a half turn); there is also rotation_degrees. Click the revert arrow to return to 0.
  7. Try snapping. In the toolbar find Use Grid Snap (a grid icon) and the three-dots menu next to the snap buttons. Click the three dots, choose Configure Snap…, set Grid Step to 32 by 32, and close. Turn on Use Grid Snap, switch to Move mode and drag the icon: it jumps in 32-pixel steps and the viewport rulers' numbers adapt. Hold Shift while dragging to lock to one axis. In the same dots menu you can enable Use Rotation Snap (step in degrees) and Use Scale Snap. Afterwards turn Use Grid Snap off and re-enter (576, 324). (Use Smart Snap, next to it, snaps to the edges and centers of other nodes; try it later.)
  8. Pivots. Rotation happens around a node's origin. Select Icon, in the Inspector find Offset (a section of Sprite2D) and untick Centered. The picture jumps: its top-left corner is now at the node's position, because "centered" had been placing the origin at the picture's middle. Press E and rotate: it now swings around its corner. Tick Centered again. For quick one-off experiments there is also the Rotation Pivot tool in the toolbar (click it, click a point, then rotate with E); that pivot is only an editor helper and is not saved.
  9. Zoom and pan the view. Scroll the mouse wheel over the viewport to zoom (the zoom box at the top-left of the viewport shows the percentage; clicking the number resets to 100%). Hold the middle mouse button and drag to pan (alternatively hold Space and drag with the left button, or press G for the Pan tool). Click Center View (top-left of the viewport), or press F, to center the selected node, and Shift+F to also zoom to fit it. The black bars along the left and top edges are rulers; drag from one into the viewport to create a purple guide line.
  10. Viewport versus window. The indigo rectangle is the game viewport: the size, in pixels, the game thinks its screen has. It is set in Project > Project Settings > Display > Window > Size (Viewport Width and Viewport Height; default 1152 × 648). The window the player sees may be larger or smaller, and what happens then is controlled by the stretch settings (section 10). The editor's own big canvas area, which you zoom and pan, is a different thing again: it is infinite, and only the part inside the indigo rectangle appears in the game. You can hide the rectangle with the viewport's View menu.
  11. Add a Camera2D. Click the root Playground2D, press Ctrl+A, type Camera2D, select it and click Create. A camera frame (a rectangle with the size of the game window) appears around the origin. Press F6: the icon is now at the bottom-right corner of the window, half cut off. Reason: with a camera, the window shows the world centered on the camera, and your camera is at (0, 0). Stop (F8).
  12. Move the camera onto the icon. Select Camera2D, set its Position to (576, 324), press F6: the icon is centered again. Now set Zoom (Inspector) to 2, 2 and run again: everything looks twice as large (zoom above 1 magnifies). Set Zoom back to 1, 1. You will use Camera2D constantly from Day 5 on; for now know that no camera = world (0,0) is the top-left of the window; with a camera = the camera's position is the center.
  13. See transforms inherit through the tree. Right-click Icon in the Scene dock and choose Add Child Node, search Sprite2D, Create, and rename it Satellite. Drag icon.svg from the FileSystem dock onto its Texture slot. Set Satellite's Position to (200, 0) and Scale to 0.4, 0.4. Now select Icon and set its Rotation to 45: the satellite orbits with it. A child's transform is relative to its parent (position (200, 0) means 200 pixels to the right of the parent, in the parent's rotated space). This is why moving a character moves its weapon, shadow and camera. In code, position is local and global_position is in world space.
  14. Save. Press Ctrl+S. The scene tab title loses its asterisk (an (*) after a name means unsaved changes).

7. The 3D workspace, briefly (about 15 minutes)

Part 1 has two 3D games (Days 10-13), and Day 10 teaches 3D properly. Today you only need to be able to look around and not be scared of the 3D viewport.

  1. New 3D scene. Scene > New Scene, click 3D Scene (root Node3D). The editor switches to the 3D workspace automatically. Rename the root Playground3D and save it as res://day01/playground_3d.tscn. The viewport shows a grid and three colored axis lines.
  2. Add a box. Select the root, press Ctrl+A, search MeshInstance3D, Create. In the Inspector, the Mesh property says <empty>: a MeshInstance3D only draws a mesh resource you give it. Click the property and choose New BoxMesh. A 1 × 1 × 1 metre cube appears at the origin.
  3. Learn the 3D toolbar. Hover the first five tools. In 3D they are Transform Mode (Q, move + rotate combined), Move Mode (W), Rotate Mode (E), Scale Mode (R) and Select Mode (V). Note that 2D uses Q for select and S for scale; 3D differs.
  4. Orbit, pan, zoom. With the mouse over the 3D viewport: hold the middle mouse button and drag to orbit around what is on screen; hold Shift + middle mouse and drag to pan; scroll the wheel to zoom. Press F with the cube selected to focus on it. (Trackpad: you ticked Emulate 3 Button Mouse earlier; the docs list the modifier keys it uses under the editor settings tooltip.)
  5. Fly mode. Hold the right mouse button and move the mouse to look around, and while holding it press W A S D to fly, E to go up and Q to go down. Hold Shift to fly faster, Alt to go slower; the mouse wheel while flying changes the base speed. Release the button to leave fly mode. This is the view's free-look mode, available when the viewport is in Perspective view.
  6. Use the view gizmo. Top-right of the viewport is a small coloured axis gizmo. Click one of the coloured circles to snap to a straight-on view (front, top, side: the viewport switches to Orthogonal); click-and-drag the gizmo to orbit. The three dots at the top-left of the viewport open its view menu, which shows the current view type (Perspective or Orthogonal). Press F again to refocus. Switch back to Perspective from that menu.
  7. Axes and orientation. The colors are RGB = XYZ: red X, green Y, blue Z. In Godot 3D, Y is up, X is sideways, Z is front/back, and the coordinate system is right-handed. By convention Godot's "forward" is -Z (the class reference defines Vector3.FORWARD as (0, 0, -1)), so a camera looks toward negative Z. Units are metres.
  8. Move the cube with gizmos. Select the MeshInstance3D node and press W: three arrows (red, green, blue) appear on the cube. Drag one to move along that axis; drag a small coloured square to move within that plane. Press E: coloured arcs rotate around each axis. Press R: cubes scale. Hold Ctrl while dragging to snap to steps. T toggles Use Local Space (gizmo follows the node's own rotation). Press Ctrl+Z until the cube is back at (0, 0, 0), or type zeros into Transform > Position.
  9. The preview sun and environment. In the 3D toolbar, find the two toggle buttons Toggle preview sunlight and Toggle preview environment and the three-dots button beside them. The cube looks lit and the background shows a sky only because of these editor-only previews, used when the scene has no real light or WorldEnvironment. Click the sun toggle off: the cube turns dark. Click it on again. Neither preview exists in the running game.
  10. Add a Camera3D. Select the root, Ctrl+A, Camera3D, Create. Set its Transform > Position to x 0, y 0.5, z 3. With the camera selected a Preview check box appears at the top of the viewport: tick it to see through the camera (you look along -Z toward the cube), untick it to return to the editor view. A game without a current Camera3D renders nothing.
  11. Run it and see why lights matter. Press F6. The cube looks dull and flat compared to the editor view, because the previews do not exist at runtime. Stop (F8). Select the root, Ctrl+A, add a DirectionalLight3D, and in its Transform > Rotation set x = -50, y = 30, z = 0. Run again: the cube now has a bright face and dark faces. When a real DirectionalLight3D exists, the preview sun is no longer used.
  12. Know that WorldEnvironment exists. A WorldEnvironment node (given an Environment resource) is how a 3D scene gets its sky, ambient light, fog, glow and tone mapping at runtime. Do not add it today; Day 10 does. Save the scene with Ctrl+S.

9. The Game workspace and the embedded game window (about 10 minutes)

The Game workspace is where a running game shows up in the editor. You can pause it, step it one frame at a time, slow it down and click nodes inside it to inspect them. To have something that moves to practice on, you attach a three-line script to the icon in the 2D playground (full explanation tomorrow).

  1. Make the icon spin. Open the playground_2d.tscn tab. In the Scene dock, right-click Icon (the first Sprite2D) > Attach Script, set Path to res://day01/spin.gd, click Create, select all, and replace the contents with the listing. Save with Ctrl+S.
  2. Open the Game workspace. Click Game (top center). Without a running game it shows a hint to run the project. In the top-right corner of its bar there is a drop-down menu; open it. The documented default is: game in a floating window with a Game bar on top. Leave the defaults.
  3. Run the playground. Press F6. The big icon spins and the small one orbits. Notice the Game bar in the game window.
  4. Pause and step. On the Game bar click Pause (F9): the animation freezes (physics and processing stop; rendering and input continue). Click Frame advance (F10, enabled only while paused) several times: the icon moves one frame at a time. This is how you study a one-frame glitch. Click pause again to resume.
  5. Change the game speed. Open the Game speed menu on the Game bar and choose a slower value such as 0.25×: the spin slows down. Use the reset button next to it to return to 1.0×. (Physics runs at the scaled speed as well, which is perfect for watching collisions.)
  6. Inspect a running node. Pause the game again. Switch the interaction mode on the Game bar from Input to 2D, then click the spinning icon. An orange rectangle selects it, and the editor's Inspector shows that node's live properties. You can even edit them; look at Rotation change. Also look at the Scene dock: while a game runs it offers a Remote view of the live scene tree next to the normal Local one.
    Changes in the running game are not saved

    Anything you change through the Game window or the Remote tree is lost when the game stops. To tweak and keep a value while the game runs, edit the node in the Local tree instead (with Debug > Synchronize Scene Changes enabled so the running game sees your edit).

  7. Try embedded mode. Stop the game (F8). Open the Game workspace drop-down again and untick Make Window Floating on Next Play (keep Embed Game on Next Play ticked). Press F6: the game now runs inside the editor's Game workspace. Pick whichever mode you like. Floating suits a second monitor; embedded is convenient on one screen. The game always runs in a separate process, so a crashing game never crashes the editor. Embedding has limits (for example, window-mode changes such as fullscreen do not work embedded); if a project later behaves oddly, choose Make Window Floating on Next Play or disable embedding to see the game exactly as an exported one.
  8. Stop the game. Press F8.

You paused the spinning icon with F9, advanced it a frame with F10, slowed the game down, and inspected the running icon's properties. If F9/F10 do nothing, click inside the game window first so it has keyboard focus; if the Game bar is missing, embedding is disabled (it is configured from the same drop-down).

  3. The Advanced Settings toggle. At the top-right of the window is a switch labelled Advanced Settings. By default Godot hides rarely-used settings. Turn it on. Many more categories and entries appear (for example the project's Window Width Override, Debug > GDScript warnings, and so on). Leave it on for the rest of the course so that names in the text match what you see.
  4. Application > Run > Main Scene. Search main scene. This is the setting F5 reads. It should point to day01/hello.tscn. (We change it tomorrow.)
  5. Display > Window > Size. Search viewport width. Viewport Width and Viewport Height are the base size of your game: 1152 and 648 by default. Neighbouring settings include Mode (windowed, fullscreen ...) and Resizable. All Part 1 2D games use 1152 × 648 except Dodger (480 × 720); the portrait Part 2 games use 720 × 1280.
  6. Display > Window > Stretch. Search stretch. Mode decides how your 1152 × 648 base size is fitted to a window of a different size: disabled (no scaling; one unit is one pixel), canvas_items (2D is drawn at the window's real resolution, scaled up: good for most games) and viewport (render small, scale the image: pixel art). Aspect says what to do when the window shape differs from the base shape: keep (add black bars), expand (show more of the world) and others. Engine defaults are disabled and keep; projects created from Godot 4.7 start with canvas_items and expand. Set Mode to Canvas Items and Aspect to Keep (the course default for the Part 1 2D games). Close the window, press F5 and drag the game window's corner to resize it: the content scales and black bars appear. Switch Aspect to Expand and repeat to see the difference. Set it back to Keep.
  7. Layer Names. In the left tree click Layer Names > 2D Physics. It lists Layer 1 to Layer 32 with empty name fields. Physics bodies live on layers and only see layers in their mask; naming them turns checkbox grids into readable lists. Type these seven names (the ones every game in this course uses), clicking each field in turn: world, player, enemies, player_attacks, enemy_attacks, pickups, triggers. (Names are per project, and you repeat them in each game project. Nothing here changes behaviour yet.)
  8. See what it wrote. Close the window and run in PowerShell:

    Find the lines you caused: run/main_scene=... under [application], the [display] section with the stretch settings, and a [layer_names] section with 2d_physics/layer_1="world" and so on. The file only stores values you changed from the defaults.

  9. Peek at Input Map and Autoload (tomorrow's tools). Open Project > Project Settings again. On Input Map, tick Show Built-in Actions: the ui_* actions (ui_accept, ui_left, ...) already exist for menus and UI. Untick it. On Globals look at the Autoload list (empty). Close the window.

With F5, the Hello Godot window opens, can be resized, and keeps its proportions with black bars; project.godot contains your layer names. If the F5 window does not show Hello Godot, recheck Application > Run > Main Scene.

Common pitfalls

  • Downloaded the .NET build (or a beta). The .NET build is bigger and expects C#. Run only the standard stable build. If you already created projects with the wrong build, they still open in the standard editor.
  • Ran Godot from Downloads or inside the zip. Shortcuts break when you clean up, and Windows may refuse to write settings. Always run from C:\Godot\.
  • Pressed F6 and F5 interchangeably. F6 runs the scene tab you are looking at; F5 runs the main scene. "My change does not show" is most often "I ran the other one".
  • Forgot to save the scene. An asterisk next to the tab name means unsaved changes. Running with F5/F6 normally saves first, but a crash or force-closing the editor will not.
  • Mixed tabs and spaces. Typing with a different indentation style than the pasted code gives "Mixed use of tabs and spaces". Fix: set the Editor Setting to Spaces / 4 (section 4); then select the file's contents and use Edit > Indentation > Convert Indent to Spaces in the script editor.
  • Wrong workspace. "I cannot see my 2D scene": you are on the 3D or Script workspace. Click 2D. A new scene with a Node3D root opens 3D; a Node2D or Control root opens 2D.
  • Renaming or moving files in Explorer. Godot then cannot update references inside scenes. Rename and move in the FileSystem dock (drag and drop, or right-click > Rename).
  • Backslashes in paths in code. Use res://folder/file.tscn and forward slashes, even on Windows.
  • Put the project in a synced folder. OneDrive/Dropbox locking files in .godot/ causes random import errors. Keep projects in C:\GodotProjects\.
  • A dock disappeared or the layout is a mess. Editor > Editor Layouts > Default resets everything. It does not touch your project.
  • Forward+ project will not start on an old GPU. Change the renderer from the drop-down at the top-right of the editor to Compatibility, or create the project with Compatibility.

Check yourself

The project's main scene is hello.tscn, but the active scene tab is other.tscn. What do F5 and F6 run?

  • Both run other.tscn, the one you are editing
  • F5 runs other.tscn, F6 runs hello.tscn
  • F5 runs hello.tscn (the main scene), F6 runs other.tscn (the current scene)

F5 = Run Project = the main scene from Project Settings (application/run/main_scene). F6 = Run Current Scene = whatever scene tab is active. Mixing them up is the classic "why does my change not appear?" bug.

Which description of the default editor layout is correct?

  • The Scene dock lists the files of res://; the FileSystem dock lists the nodes of the open scene
  • The Scene dock lists the nodes of the open scene; the FileSystem dock lists the files of res://; the Inspector shows the properties of the selected node
  • The Inspector lists the project's files; signals are in the bottom panel's Output tab

Scene dock (top-left) = node tree; FileSystem dock (bottom-left) = project files; Inspector (right) = properties of the selected node, next to it the Node tab (Signals and Groups). The bottom panel hosts Output, Debugger, Audio, Animation and so on.

Your game must write a save file while running, even after being exported. Where should it write, and where is that on Windows by default?

  • user://, which is %APPDATA%\Godot\app_userdata\<project name> by default
  • res://, which is the project folder, always writable
  • C:\Godot\, next to the editor

res:// is read-only in an exported game (it is packed). user:// is created for you per user and per game and is guaranteed writable; in Part 2 you can switch to a custom user dir name.

A Sprite2D has position = Vector2(100, -50) and no parent offset. Where is it relative to the origin?

  • 100 right and 50 down
  • 100 right and 50 up
  • 100 left and 50 up

In Godot 2D, positive X is right and positive Y is down, so a negative Y moves up. Vector2.UP is (0, -1).

Which folder is safe to delete while Godot is closed, and should be kept out of version control?

  • day01/ with your scenes
  • The .import files next to your assets
  • .godot/

.godot/ is a regenerated cache. .import files hold real import settings and must be committed, and your scenes are your project.
