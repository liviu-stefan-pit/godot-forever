Concepts you need first

Read this once (about 15 minutes). The builds afterwards are the clicks. You already know objects, events and prefabs; the new part is where Godot puts each of those.

Nodes, scenes, instances

A node is one object in a tree (a sprite, a timer, a label). A scene is that tree saved as a .tscn file. Instancing drops a live copy of that file into another tree. The copy is one node from the outside; opening it in the Scene dock shows the children.

Think of the scene file as a prefab. Editing the file updates every copy. Editing a property on one copy writes an override on that copy only: the Inspector shows a grey revert arrow beside the property. A resource (a .tres, a texture, a shape, your own ItemData) is shared by default, like a ScriptableObject reference. Two copies that point at the same .tres see each other's edits. Make Unique clones that resource for one copy so later edits stay local.

From code, a scene file is a PackedScene. preload loads it at parse time. instantiate() builds a node tree. add_child() inserts it, which is what actually runs _enter_tree and _ready. queue_free() deletes the node at the end of the frame, children included.

GDScript, short version

You writeIt means
var speed: float = 280.0Static type. Do this by default.
var label := "gem":= infers the type. Use it when the right-hand side is obviously String, Vector2, a new(), or a cast. Skip it when the value would be an untyped Variant.
Array[String], Dictionary[String, int]Typed collections. A wrong element is an error.
match n:A switch. Patterns can list values (2, 3:). _: is the wildcard.
var f: Callable = func (n: int) -> int: return n * 2A lambda. Call it with f.call(n). It captures locals by value.
await get_tree().create_timer(0.4).timeoutSuspend this function until the one-shot timer fires. The rest of the frame keeps running.
class_name ItemDataRegisters the script as a global type. It then shows up in the Create Resource dialog and in type hints.
@export / @onreadyInspector property / assign this node reference just before _ready.

Script order used for the rest of the course: extends, class_name, signals, constants, @export, variables, @onready, lifecycle, then methods. Names: snake_case for functions and files, PascalCase for classes and node names, SCREAMING_CASE for constants.

Initialization and lifecycle

Member setup, in order:

  1. The variable exists (numbers are 0, objects are null).
  2. Initializers run top to bottom. @onready initializers wait.
  3. _init() runs. The node is not in the tree. $Child fails here.
  4. If this object came from a scene or a .tres, saved @export values are applied.
  5. @onready lines run. $Child and %Unique work.
  6. _ready() runs.

When a parent enters the tree: the parent's _enter_tree, then each child's _enter_tree, then each child's _ready, then the parent's _ready. Children are ready before the parent is.

CallbackWhenPut here
_initObject constructedPlain data. No node paths.
_enter_treeJoined the treeRare. Parent exists; siblings may not be ready.
_readyThis node and its children are in the treeConnect signals, cache nodes, spawn.
_process(delta)Every drawn frameVisuals, UI, non-physics motion. delta is seconds since the previous frame and varies.
_physics_process(delta)Fixed rate, 60 Hz by defaultPhysics and anything that must stay stable if the frame rate drops. delta is 1/60 unless you change the physics tick rate.
_unhandled_input(event)An input event nobody handled yet (UI first)Gameplay keys and clicks that a button should be allowed to swallow.

position += direction * speed * delta keeps speed in pixels per second. Drop delta and the icon moves faster on a 144 Hz monitor than on a 60 Hz one.

Signals, groups, names

A signal is a typed event. clicked.emit(1) calls every connected function. Connect in the editor (Node tab > Signals, double-click, Connect) or in code (icon.clicked.connect(_on_icon_clicked)). Callable.bind appends extra arguments after the ones the signal already sends: clicked(points) connected with .bind("icon") calls _on_icon_clicked(points, "icon").

A group is a tag. add_to_group("pickups") or the Groups dock. Later, get_tree().call_group("pickups", "flash") calls flash on every member. The course uses the group name pickups spelled exactly that way.

$Icon is a path from this node. It breaks if you reparent Icon. %ScoreLabel finds a node you marked Access as Unique Name (a % appears beside it in the Scene dock). Unique names are looked up inside the same scene. @onready var score_label: Label = %ScoreLabel stores the reference once, which is what you want; calling $ every frame walks the tree again.

Input, timers, autoload

An action is a name (move_left) mapped to keys or buttons. Read held movement with Input.get_vector("move_left", "move_right", "move_up", "move_down"): negative X, positive X, negative Y, positive Y, length at most 1. Read a tap with Input.is_action_just_pressed("jump"). Inside _unhandled_input, the class reference prefers event.is_action_pressed("jump") for that single event; you will see both today.

A Timer node lives in the tree. You set Wait Time, One Shot and Autostart, then connect its timeout signal. get_tree().create_timer(2.5) is a one-shot with no node, used as await ...timeout when you only need to pause a function.

An autoload is a node Godot creates before your scene and keeps until the run ends. Its Node Name (Score) is the global you call. Give the autoload that name in Project Settings; do not also put class_name Score on the script, or the two globals collide.

7. Output versus Debugger (about 15 minutes)

print is a log line. push_error is a failure with a stack. A breakpoint pauses on a line you choose. You will try each once, then put the scripts back.

  1. Breakpoint. Open click_icon.gd. Click the gutter immediately left of the line number on Score.add_points(points, source) inside _on_icon_clicked. A red dot appears. That dot is stored by the editor.
  2. Hit it. F5, click the logo. The game pauses. The bottom panel switches to Debugger, Stack Trace. A green arrow in the script gutter marks the line. In the stack variables you can read points and source (source is icon, which is the bound argument).
  3. Continue. In the Debugger toolbar click Continue. The toy finishes the click (score, spawn). Press F8. Click the red dot again so the breakpoint is gone. If you leave it, every future click pauses.
  4. Force an error. In _ready, as the first line inside the function, add push_error("Day 2: error on purpose"). Save. F5. Open Debugger > Errors. The message is listed there with a stack. print lines stay on the Output panel's log. Stop with F8.
  5. Remove the error line. Delete push_error(...) so _ready matches the listing again. Save. F5 once more: the Errors tab does not add that message, and the toy still scores. Stop.

With the breakpoint removed and the push_error line gone, F5 plays the toy with no new error. Output still shows the Score ... from ... lines. If the game pauses on click, the red dot is still in the gutter.

Common pitfalls

  • F5 still shows Hello Godot. The main scene is still res://day01/hello.tscn. Set click_icon.tscn as the main scene. F6 never consults that setting.
  • The click adds 2 points. input_event or clicked is connected twice (once in the Signals dock and once in _ready, or two editor connections). Disconnect the extra one. The listing connects clicked only in code, and input_event only in the editor.
  • Node not found for $Icon or %ScoreLabel. The node was renamed, the unique-name toggle is off, or the path is used inside _init. @onready and _ready are the places those paths work. Renaming a node in the Scene dock updates editor signal paths; renaming the .gd file in File Explorer does not.
  • Every gem's points change together. They still share gem_data.tres. Right-click that instance's Data property and choose Make Unique before editing.
  • The icon does not move, and Output names a missing action. The Input Map entry is spelled differently from the string in get_vector. The five names are move_left, move_right, move_up, move_down, jump.
  • Clicks miss the logo. Hit has no RectangleShape2D, the shape is tiny (default size is 20×20 until you set 128), or Collision > Layer has every box cleared. input_pickable must stay on.
  • The editor connection does nothing after you replaced the script. The receiver method was renamed. The scene still calls _on_hit_input_event.
  • await inside _ready feels like it froze the game. Only that function is suspended. The icon keeps moving. Code you place after the await in gem.gd runs 2.5 seconds later, which is why emit and queue_free happen then.
  • A new .tres will not open. ItemData._init has a parameter without a default. The Inspector calls _init() with zero arguments.
  • Score is an error, or there are two Score types. The autoload Node Name must be Score, and score.gd must not declare class_name Score. Do not queue_free() an autoload; the engine crashes if you remove it that way.
  • The Scene dock looks empty of your nodes while the game runs. It is on Remote. Click Local.

Challenge (optional, 20-30 min)

Spawn another gem on purpose

The toy spawns one gem, then ignores further spawns. Add the course action confirm (Enter) and make Enter spawn an extra gem that also adds its points when it disappears. Keep the click behaviour.

Hints
  • Input Map: action name confirm, key Enter. Later days use that same name.
  • The boolean _spawned is what blocks the second spawn. A second call needs a way around that flag without spawning a gem on every click.
  • Poll Input.is_action_just_pressed("confirm") from _process on the icon or on ClickIcon. The icon can emit another signal; the root already knows how to instantiate, connect collected, and add_child.
  • Callable.bind can pass a different source string than "icon" so Output tells the two spawns apart.
  • Score.reset() already exists if you want a third key to zero the label. Connect it the same way as points_changed.
  • Each gem waits 2.5 seconds on its own create_timer. Two gems in group pickups both receive flash from call_group.

Check yourself

You instance gem.tscn twice and change Position on one copy. A grey revert button appears beside Position. What is true?

  • The source scene's Position is now the value you typed, and both copies move.
  • Only this copy stores an override. Other copies, and the source scene, keep their own Position. The revert button writes the source value back onto this copy.
  • Make Unique ran automatically, so the sprite texture was duplicated on disk.

A property override is per instance. Saving the source updates copies only where they do not override that property. Make Unique is a separate action, used when the thing you are editing is a shared resource such as gem_data.tres.

Where can $Sprite succeed on a node that owns a child named Sprite?

  • Inside _init, because the children are constructed first.
  • In an @onready variable and inside _ready, after this node has entered the tree.
  • Only inside _physics_process, because $ is a physics lookup.

_init runs before the node is in the tree, so child paths fail. @onready assignments run after enter-tree setup and before _ready. $ is get_node, not a physics call.

signal clicked(points: int) is connected with _on_icon_clicked.bind("icon"). The icon runs clicked.emit(1). What does _on_icon_clicked receive?

  • Only the string "icon". Bind replaces the signal arguments.
  • points = 1, then "icon". Bound arguments are passed after the ones the signal emitted.
  • "icon" first, then 1. Bind always inserts at the front.

Callable.bind appends. The handler is _on_icon_clicked(points: int, source: String). The Advanced mode of the Connect a Signal window binds extra arguments the same way.

What does Input.get_vector("move_left", "move_right", "move_up", "move_down") use each string for?

  • Negative X, positive X, negative Y, positive Y, in that order. The result's length is at most 1.
  • Up, down, left, right. The parameter names in the call are just comments.
  • Four keyboard scancodes, read from the operating system, ignoring the Input Map.

The signature is get_vector(negative_x, positive_x, negative_y, positive_y). In 2D, negative Y is up, which is why move_up is the third argument. The strings are Input Map actions, so the keys can change without editing the script.

While the game runs, where do print("hi") and push_error("hi") show up?

  • Both only in the script editor gutter, as red dots.
  • print is a log line on the Output panel. push_error is listed on Debugger > Errors with a stack trace.
  • Both only on Debugger > Stack Trace, and only after a breakpoint.

Output is for print. push_error and push_warning are reported on the Debugger Errors tab so they stay distinct from logs. A breakpoint is a third tool: it pauses on a line and opens Stack Trace.
