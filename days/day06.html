Concepts you need first

One enum, one match

A platformer character is always in exactly one mode. Dash ignores gravity. Hurt ignores input. Jump can become Fall, but it cannot also be Idle. An enum makes that exclusive, and match is the switch. This is the same idea as a Unity Animator state or an Unreal enum used to pick a movement function: one variable, a function per state, transitions written in one place.

Today's states:

StateWhat it is allowed to do
IDLE / RUNGround acceleration, jump (coyote + buffer), dash if unlocked. Leaving the floor becomes FALL.
JUMP / FALLAir control, jump-cut, one extra jump if has_double_jump, dash if unlocked. Touching the floor returns to ground.
DASHFixed horizontal speed, no gravity, for 0.16 s. Then IDLE or FALL.
HURTKnockback velocity, input ignored. After 0.28 s, back to IDLE or FALL. At 0 hearts, respawn at the spot the player started.
Why not a child node per state?

Godot can do states as child nodes (each with its own script, the parent enables one). That scales when a state needs its own nodes. Cave Runner has six small states that all share one body, so an enum keeps the Day 5 movement maths in a single file you can read top to bottom. Later games in this course can use node states; do not mix the two styles in this project.

Hurtbox and hitbox are both Area2D

An Area2D detects overlaps. It does not push anything. The convention for the rest of Cave Runner:

  • Hurtbox (on the player): "I can be hit." Layer player, mask enemy_attacks. Its script listens to area_entered.
  • Hitbox (on the slime): "I deal damage." Layer enemy_attacks, mask empty. It only needs to be monitorable so the hurtbox can see it.

The player's CharacterBody2D still masks only world, so the slime's body (layer enemies, mask world) does not shove the player. Touch damage is the overlap of the two areas, not a body collision. Spikes are the exception: they are solid tiles, and the player reads the damage custom data Day 5 stored on that tile.

Ability flags

Dash and the second jump exist in the script from the start. Two bools, has_dash and has_double_jump, default to false. Orbs call grant_ability. A Metroidvania gate is a flag plus geometry that assumes the new move, not a second player scene.

Block 4: Spikes, knockback, and the slime

Spike damage is already in _check_hazards. After move_and_slide(), each slide collision against a TileMapLayer is turned into a cell with get_coords_for_body_rid. That cell's TileData.get_custom_data("damage") is the int you set on the spike tile. Rock tiles return 0. The Hazards layer's quadrant size of 1 (set on Day 5) is what makes the cell exact. Standing on spikes calls take_damage once, then the invulnerability timer ignores the next overlaps for 0.85 s while the sprite flickers.

Common pitfalls

  • Two scripts fighting over frame. The Day 5 _update_sprite function is gone because you replaced the file. If you merged by hand and left it in, the AnimationPlayer and that function take turns and the sprite strobes.
  • Calling move_and_slide() inside a state function and again after the match. The body moves twice per frame and tunnels. The listing calls it once, after match.
  • Hurtbox mask left at the default (bit 1, world). It detects tiles, not the slime's hitbox, so contact does nothing. Layer and mask are different rows.
  • Hitbox layer left at bit 1. The hurtbox is looking for enemy_attacks. Both sides have to agree.
  • Connecting area_entered in the editor and in _ready. One touch deals two damage. Use only the code connection.
  • RayCast mask includes enemies or player, or Exclude Parent is off. The slime sees itself and spins in place.
  • Forgetting force_raycast_update after moving the ray. The turn happens one frame late and, on a thin ledge, one frame late is already off the cliff.
  • Spike cell is wrong. get_coords_for_body_rid returns the physics quadrant, not the tile, unless Physics Quadrant Size on Hazards is 1.
  • Animation names differ by a capital letter. play() does not fuzzy-match. The Output line is Animation not found.
  • Player mask changed to include enemies. The bodies collide and the slime pushes you. Keep the body mask at world only. Damage is the areas' job.

Challenge (optional, about 25 min)

Stomp the slime

Falling onto a slime should bounce you and remove the slime, instead of hurting you. Use frame 2 of slime_sheet.png for a short squash before queue_free().

Hint

In the hurtbox handler, if the player state is not HURT and velocity.y > 0 and player.global_position.y < area.global_position.y, call a new stomp() on the slime (area.owner when the hitbox scene is instanced under the slime) and set player.velocity.y to the jump velocity. Give the slime class_name Slime so the check is typed. Do not also call take_damage on that path. The flat sprite is sprite.frame = 2; wait with await get_tree().create_timer(0.12).timeout before freeing. Disabling the hitbox shape for that wait needs set_deferred("disabled", true) if you do it inside the area callback.

Check yourself

Why does this player use one enum State and a match, instead of six independent bools?

  • Godot 4 removed bool variables on nodes
  • Exactly one state is active, so dash cannot also run the ground acceleration code in the same frame
  • Enums are the only way to call move_and_slide()
  • match is required for AnimationPlayer

The point of the enum is exclusivity. Each branch owns its rules, and transitions are assignments to state. Node-per-state is a valid alternative; this project committed to the enum.

The slime overlaps the player and nothing happens. Which pairing is the one this project uses?

  • Player body mask includes enemies, slime body layer is enemies
  • Both areas are on layer world
  • Hurtbox masks enemy_attacks and listens to area_entered; the hitbox's layer is enemy_attacks and it is monitorable
  • The hitbox calls move_and_slide()

Areas detect overlaps when the detector's mask includes the other area's layer, monitoring is on, and the other area is monitorable. The bodies are deliberately not colliding with each other.

You changed FloorRay.target_position this frame and immediately read is_colliding(). What do you call first?

  • force_raycast_update()
  • move_and_slide() on the ray
  • Nothing; rays query on demand when you read them
  • queue_free() on the ray

A RayCast2D stores the hit it found on the physics frame. After you move it, force_raycast_update() recomputes now.

Standing on the spike tile hurts once, then not again until the flicker ends. What stops the second hit?

  • Tile custom data only works on the first frame
  • move_and_slide() disables the tile
  • The Hazards layer deletes the cell
  • _invuln_timer makes take_damage return immediately

The tile stays solid and keeps reporting damage == 1. The timer is the cooldown. Without it, three hearts would vanish in three physics frames.

Which value on the spike tile decides how many hearts a touch costs?

  • The tile's atlas coordinates alone
  • Custom data layer damage, read with TileData.get_custom_data("damage")
  • The TileMapLayer's modulate
  • collision_layer bit 5

Day 5 added an int custom data layer named damage and set it to 1 on atlas cell (5, 0). Rock tiles stay at 0, so walking on the floor does not hurt.
