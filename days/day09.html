Concepts you need first

Clicks are pixels, rules are cells

local_to_map expects a position in the TileMapLayer's own coordinates. The mouse is in global coordinates, so the conversion is map.local_to_map(map.to_local(get_global_mouse_position())). The reverse, for dropping a tower on the cell centre, is map.to_global(map.map_to_local(cell)). get_cell_tile_data(cell) returns null off the map; otherwise get_custom_data("buildable") is the bool you painted on Day 8. Path and rock stay false, so the route cannot be walled off. That is why this game stays on Path2D.

One detector, two layers

The enemy Hitbox is already on layer 3 (enemies), monitorable, and watching nothing. Towers and shots do the looking. Their Area2D nodes sit on layer 4 (player_attacks) and their mask is only layer 3. In the Inspector those are the named buttons. In code the same masks are bit values: layer 3 is 4, layer 4 is 8 (layer 1 is bit 0). A physics shape query does not see areas unless collide_with_areas is true; the default only tests bodies, and our enemies are areas.

Aim, splash, slow

A tower picks one enemy inside its range circle: First (highest progress_ratio on that enemy's own path), Last, Closest, or Strongest (current health). It leads the shot with predict_position from Day 8. Cannon shells deal their full damage to every enemy in the splash radius. Frost multiplies speed by slow_factor (0.55 means 55% speed) through apply_slow, which already keeps the strongest factor and the longest duration. Frost level 3 also splashes that slow.

Time scale and the save file

Engine.time_scale = 2.0 scales _physics_process delta and SceneTreeTimer together, so the wave and the towers speed up as a pair. It does not reset when you reload the scene, and it does not speed audio (there is no audio today). JSON.parse_string turns every number into a float, so a saved 3 comes back as 3.0. Cast with int() before you store the best wave.

Common pitfalls

  • Passing the global mouse into local_to_map. The cell is wrong by whatever the layer's position is, and it gets worse the moment you move Map. Convert with to_local first. Place with to_global(map_to_local(cell)) so the tower sits on the centre, not the corner.
  • The query ignores areas. PhysicsShapeQueryParameters2D.collide_with_areas defaults to false. Enemy hitboxes are areas on layer 3. A mask of 4 with bodies-only hits nothing, and every shot flies off the map.
  • Layer buttons versus bit values. Inspector button 4 is value 8. Writing collision_layer = 4 puts the shot on the enemies layer. The scripts set 8 and 4 on purpose.
  • Engine.time_scale survives the reload. Dying at 2× and restarting without setting it back leaves the next run sped up, and the button label lies until you click it. Both Game.reset and the Restart button set it to 1.0.
  • Treating the JSON number as an int. best_wave would become a float and later comparisons get sloppy. int(parsed.get("best_wave", 0)) is the whole fix.
  • Selling without freeing the cell. _occupied.erase(cell) has to happen or that grass tile is dead for the rest of the run. The refund goes through Game.add_gold, not by editing the label.
  • A full-rect Control on Stop. Overlay must be hidden during play. Labels must be mouse filter Ignore. Otherwise _unhandled_input never sees the click and Output stays silent.

Check yourself

The mouse position is global. How do you get the tile cell?

  • Pass get_global_mouse_position() straight into local_to_map.
  • local_to_map(map.to_local(get_global_mouse_position())).
  • map_to_local on the mouse position.

local_to_map wants the layer's local space. to_local does that conversion. map_to_local goes the other way, from a cell back to a pixel centre.

Which collision setup matches this project?

  • Projectile on layer 3, mask layer 1.
  • Projectile on layer 4 (player_attacks), mask layer 3 (enemies).
  • Projectile on layer 1, and the enemy mask includes layer 4.

Enemies are monitorable on layer 3 and do not scan. Shots and tower ranges scan layer 3 from layer 4. In bit values that is layer 8 and mask 4.

You load best_wave.json and the text says {"best_wave": 4}. What is the safe read?

  • Use the value as an int. JSON preserves integer types.
  • int(parsed.get("best_wave", 0)), because JSON numbers become floats.
  • Store the record in a .tres so the type stays an int.

JSON.parse_string has only one number type. 4 comes back as 4.0. The int() cast is required for counters.

You set Engine.time_scale = 2.0 and then Restart. What is true?

  • Only the HUD animates faster. Waves ignore it.
  • Deltas and scene-tree timers both speed up, and the scale stays at 2 until something sets it back.
  • Reloading the scene always restores 1.0 on its own.

Time scale is an engine global, not a property of the scene. This project sets it back in Game.reset and in the Restart handler. The spawner's timers do not pass ignore_time_scale.

You build an Arrow (50) and upgrade it once (40), then sell. What comes back?

  • 40 gold, the last upgrade only.
  • 90 gold, a full refund.
  • 54 gold, because int(90 * 0.6) is 54.

SELL_RATIO is 0.6 of every gold piece put into that tower, truncated. A fresh arrow refunds 30. The cell is erased so you can build there again.
