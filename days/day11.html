Concepts you need first

Hitbox and hurtbox

The capsule on Player is the hurtbox: it is a CharacterBody3D on layer player. The thing that deals damage is a separate Area3D on layer player_attacks whose mask is enemies. An area reports bodies on the layers in its mask, and only while monitoring is on. Layers are "what I am"; the mask is "what I scan". Bit values, if you set them in code: layer 1 = 1, 2 = 2, 3 = 4, 4 = 8, 5 = 16.

Why the clips key Rig, and Pivot only moves

player.gd writes Pivot.rotation.y every physics frame so the creature faces its movement. A rotation track on Pivot would fight that write. Locomotion and the dodge hop key Pivot.position (the script never touches position). The swing keys Rig.rotation, which is a child, so the swing is added on top of the facing. The imported player.glb is not assumed to contain attack clips; if Model has its own AnimationPlayer, you will turn that one off.

State machine, navigation, i-frames, hit-stop

An AnimationTree does not store clips. It points at an AnimationPlayer and blends them. A transition whose Advance Mode is Enabled runs only when code calls travel(). Auto plus Switch Mode: At End returns to idle when the clip finishes. NavigationAgent3D does not move the body: you set target_position, call get_next_path_position() every physics frame, and feed the direction to velocity and move_and_slide(). I-frames are a timer that makes take_damage return. Hit-stop sets Engine.time_scale below 1 for a few real-time milliseconds; the wait must use create_timer(..., true, false, true) or the slowed clock stretches the wait and the game stays slow.

Block 3: The AnimationTree

  1. Add the tree. In player.tscn, select Player, add an AnimationTree. In the Inspector set Tree Root to New AnimationNodeStateMachine. Assign Anim Player by clicking Assign and picking the AnimationPlayer (do not type the path). Turn Active on. Leave Advance Expression Base Node at its default; we do not use expression conditions.
  2. Open the graph. Select AnimationTree. In the bottom panel, open the AnimationTree tab. You get a 2D graph with Start and End. Right-click empty space, choose Add Animation, and add idle, run, jump, attack, heavy_attack, and dodge. Each node is named after the clip. Do not rename them: the script travels to those strings. Drag from Start to idle. Do not connect anything to End.
  3. Connect transitions. Drag from the right side of a state to another state. Click the arrow and set the Inspector. Default Advance Mode is Enabled, which means "only when travel() asks". Use that plus Switch Mode: Immediate and Xfade Time 0.12 for: idle to run, run to idle, idle to jump, run to jump, jump to idle, jump to run, and from idle, run, and jump to each of attack, heavy_attack, and dodge. Use Xfade Time 0.05 on the three attack/dodge entries.
  4. Auto-return when the action clip ends. Add attack to idle, heavy_attack to idle, and dodge to idle. On those three arrows set Advance Mode to Auto, Switch Mode to At End, and Xfade Time to 0.08. Auto with an empty condition is always allowed, and At End waits for the clip. If a clip was left looping, also tick Break Loop At End. Save.
Missing arrow is not fatal

travel() teleports to the destination when no path of transitions exists. The arrows above are there so idle and run crossfade instead of popping. The Auto arrows are the ones that actually matter: without them, the attack pose never hands back to idle on its own.

Click AnimationTree and look at the graph: Start feeds idle, and attack, heavy_attack, and dodge each have an arrow back to idle whose Advance Mode reads Auto. The Output panel is empty. If the graph is blank, Tree Root is empty.

Common pitfalls

  • Attack keys on Pivot.rotation. The controller writes that property to face movement. Key Rig.rotation for swings and Pivot.position for bob and the hop.
  • Hitbox monitoring left on. The box then damages every enemy it overlaps, including between swings. The script forces it off outside the window; don't key monitoring on in the idle clip.
  • Changing collision inside body_entered. Turning a shape off in that callback needs set_deferred. This lesson only records the hit there and toggles monitoring from _physics_process and from the timed swing.
  • Navmesh baked from static colliders. Parsed Geometry Type stays on Mesh Instances, which includes CSGShape3D. Arena must be a child of NavigationRegion3D. Bake again after you move a pillar.
  • get_next_path_position() called from a signal. The docs warn that this can recurse. Call it from _physics_process only.
  • Hit-stop that never ends. create_timer without ignore_time_scale waits in slowed time. The Feel script passes true for that flag. Also set Engine.time_scale = 1.0 before retry, which the HUD does.
  • Pause script on a normal node. _unhandled_input does not run while the tree is paused unless Process Mode is Always. That is the HUD, not the player.
  • Two connections on one button. An editor signal plus pressed.connect in _ready runs the click twice. This page uses code only.

Check yourself

An Area3D hitbox reports an enemy body when:

  • Its collision layer is enemies and the enemy's layer is empty.
  • Its mask includes the enemies layer and monitoring is true.
  • Use Collision is ticked on the area.
  • It is a child of Camera3D.

Layer is what the area is (so other areas can find it). The mask is what it scans. body_entered and get_overlapping_bodies() both require monitoring.

How long are you invulnerable during a dodge?

  • The whole 0.45 s dash, plus the 0.55 s cooldown.
  • The first 0.28 s. After that the dash is still moving, and a hit connects.
  • Only while is_on_floor() is false.
  • Until the current wave ends.

DODGE_IFRAMES is 0.28 s and DODGE_TIME is 0.45 s. take_damage returns early only while _invuln_left is positive.

What actually moves a NavigationAgent3D enemy?

  • Setting target_position once. The agent applies velocity itself.
  • Parenting the enemy under NavigationRegion3D.
  • Calling get_next_path_position() every physics frame, then writing velocity and calling move_and_slide().
  • Enabling avoidance and waiting for the navmesh to push the body.

The agent only plans. Avoidance is a separate velocity filter and this day leaves it off. The path is empty until the region has a baked mesh and the server has synced.

A state-machine transition left on Advance Mode Enabled will:

  • Fire every frame because the condition is empty.
  • Be taken when code calls AnimationNodeStateMachinePlayback.travel().
  • Delete the clip when it finishes.
  • Run only if the AnimationPlayer's Active box is off.

Enabled means "usable by travel". Auto is what fires on its own. The attack, heavy, and dodge returns use Auto plus Switch Mode At End so they wait for the clip.

Hit-stop returns to normal speed because:

  • get_tree().paused ignores Engine.time_scale.
  • move_and_slide() resets time scale when the body lands.
  • create_timer is called with ignore_time_scale true, so the short wait is real time, and the newest call is the one that restores 1.0.
  • The AnimationTree's Xfade Time is 0.05 s.

A timer that respects time scale would wait 0.045 / 0.08 seconds of real time and feel stuck. Overlapping hits use _stop_token so an older timer cannot restore the clock early and cut a newer freeze short. Retry also forces time scale back to 1.
