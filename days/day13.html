Concepts you need first

Query rays from the physics frame

A hitscan weapon is a single segment test: "what is the first collider between the camera and a point 28 m along its look?" PhysicsDirectSpaceState3D.intersect_ray does that query immediately. RayCast3D stores the same kind of result, but it updates on the physics tick. The ray-casting tutorial runs both from _physics_process. Do not cast from _process. The physics state there can be a frame behind, and a RayCast3D read from _process is the previous tick's hit.

The shot uses the space state so you can set the mask and the exclude list per click. The interact beam is a RayCast3D under the head because its length, mask, and area-collision flag are easier to see in the Inspector. Call force_raycast_update before reading it so the hit matches the head's pose after move_and_slide.

Exclude the shooter

The camera sits inside the player capsule. Pass [get_rid()] as the exclude list. The class reference wants RIDs from CollisionObject3D.get_rid. The returned dictionary is empty when nothing is hit. On a hit, collider is the body, not the CollisionShape3D.

NavigationAgent3D

The floor cells already carry a baked NavigationMesh, and the GridMap has Bake Navigation on. An agent does not move itself. Each physics frame you call get_next_path_position, point velocity at that point, and move_and_slide. The 3D navigation introduction waits one physics_frame before the first target_position so the map has synced. Copy that. These enemies also require line of sight: a second ray on mask world | player. A closed door is on the world layer, so it blocks sight and they do not path through it. The baked mesh still connects the doorway. Sight is what keeps them honest. They are not searchers. Lose sight and they stop.

One world, two cameras

A SubViewport is a second render target. By default own_world_3d is false, so its camera sees the same GridMap as the main window. A Camera3D registers with the nearest Viewport ancestor, so the minimap camera can have Current on without stealing the first-person view. Orthogonal projection keeps a meter a meter, which is what you want on a map. size is the vertical extent in meters.

Collision changes during a physics tick

try_open runs from the player's _physics_process while the ray is resolving. Disabling the door shape is deferred with set_deferred. Turning the property off directly inside that callback is a classic one-frame glitch.

Press F5. Look at the brass doorway from the start room. The prompt says Locked. Need the brass key. You cannot walk through. The key counter still says 0, because nothing is recording pickups yet. That script is the next block. If the prompt stays empty, InteractRay's mask is missing world, or Collide With Areas is off and you are testing on a key instead of the door. If you look at a key and see no prompt, the key's layer is not pickups.

Common pitfalls

  • Ray in _process. Both the shot and the sight check belong in _physics_process. The interact RayCast3D is also read there, after force_raycast_update.
  • Forgot get_rid on the shot. The query starts inside the capsule. Without the exclude list the hit is you, and enemies never take damage.
  • Areas ignored. collide_with_areas defaults to false on both RayCast3D and PhysicsRayQueryParameters3D. Keys are Area3D nodes. The interact ray turns the flag on. The gun does not, on purpose. It only hits bodies.
  • Agent target set in _ready with no deferred wait. The navigation map is empty on the first frame. The introduction waits physics_frame. actor_setup does that.
  • target_desired_distance at 1.5 or more. The enemy decides it has arrived before the capsules touch, so HP never drops from contact. 0.5 keeps them walking into you.
  • Minimap on its own world. own_world_3d must stay false. The GridMap lives in the root world.
  • End button dead after death. A paused tree does not click controls unless that control's process mode is Always. show_end sets that on EndPanel before main.gd pauses.
  • Saved float used as an int without a cast. A later comparison can look right and still fail a typed int assignment. The load path casts with int().

Check yourself

Where does the ray-casting tutorial say to run intersect_ray?

  • _process, because aiming is visual
  • _physics_process
  • _ready, once
  • The pause menu, so the shot freezes the game

The page repeats the query inside _physics_process. RayCast3D also refreshes on the physics tick. force_raycast_update is the escape hatch when you need a result in the same tick you moved the ray.

The pistol ray starts at the camera, which is inside the player capsule. What stops the shot from hitting the player?

  • A collision layer named player_attacks on the camera
  • Calling move_and_slide first
  • PhysicsRayQueryParameters3D.create(..., [get_rid()])
  • Turning shadow casting off

The exclude list takes RIDs. get_rid is the player's physics body. The mask 1 | 4 is world plus enemies, which also skips the player layer, and the exclude is the belt the tutorial shows for self-hits.

Why does actor_setup await physics_frame before setting a target?

  • The navigation map is not synced on the first frame of _ready
  • CharacterBody3D has no velocity until the second second
  • GridMap only collides after a redraw
  • Signals cannot connect in _ready

The 3D navigation introduction says not to await inside _ready itself, and to wait one physics frame in a deferred call before set_target_position.

The minimap square shows an empty color and no floor. Own World 3D is checked. Why is the dungeon missing?

  • Orthogonal cameras cannot see MeshInstance3D
  • TextureRect ignores ViewportTexture
  • Bake Navigation hides meshes
  • The SubViewport is drawing a different World3D than the GridMap

The viewports page: SubViewports share the parent world unless Own World 3D is on. The GridMap is in the root world. Leave the flag off. The minimap camera is current only for that SubViewport.

You store best_msec with JSON.stringify and read it back. What does the load code have to do?

  • Nothing. JSON preserves ints
  • Cast with int(), because JSON numbers become floats
  • Store the file under res:// so the type sticks
  • Use File.new

JSON.parse_string does not have an integer type. int(data["best_msec"]) is the cast. The path is user://torchlight_best.json.
