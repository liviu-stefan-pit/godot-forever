Concepts you need first

What you call, and what you do not touch

The Ship Kit is a library. This game adds files under res://game/ and res://data/ and replaces the placeholder res://game/game.tscn. SceneRouter.GAME_SCENE is that path, so the file must stay there. The main scene stays res://ui/main_menu.tscn.

You will call SaveManager.save_slot, SaveManager.load_slot, SaveManager.get_value, SaveManager.set_value, SaveManager.flush, SceneRouter.go_to, Settings.set_locale, and Events.game_started, Events.toast_requested, Events.achievement_unlocked. You will not emit Events.score_changed or Events.game_over with a crumb total: both signals carry an int, and a late-game balance does not fit in an integer.

Do not add an autoload

The economy is a node inside game.tscn. A second save singleton would fight SaveManager.

Floats, strings, and 2^53

JSON numbers are IEEE floats. Every integer above 2^53 (9,007,199,254,740,992) is not representable, so a crumb counter stored as an int and written with JSON.stringify will silently skip values. The in-memory balance is a float (about 15 significant digits). The save file stores that float as text from "%.10g", and load parses it with float(). Display uses suffixes, so the digits a float cannot keep are not shown. Counts that stay small (generators owned, click count) are stored as numbers and cast with int() on load, because JSON will have turned them into floats.

Prices

Let B be base cost, g growth, n how many you already own. The next single unit costs:

P(n) = ceilf(B * g^n)

Buying k units in one click uses the closed geometric sum, then one ceil (not a ceil per unit):

P(n, k) = ceilf( B * g^n * (g^k - 1) / (g - 1) ) when g is not 1.

Worked sprout (B = 15, g = 1.15): P(0) = 15, P(1) = ceilf(17.25) = 18, P(2) = ceilf(19.8375) = 20, P(3) = ceilf(22.813) = 23. Ten sprouts from zero: 1.15^10 ≈ 4.04556, so 15 * (4.04556 - 1) / 0.15 ≈ 304.56, and ceilf makes 305. Summing the four single ceils 15+18+20+23 is 76, while the bulk formula for k = 4 ceils once to 75. The x1 button uses P(n). Tomorrow's challenge can call the bulk function. They are allowed to disagree by a crumb.

Production per second is sum(base_rate * owned * generator_mult) * global_mult. A tap adds 1 * click_mult * global_mult and does not change the per-second label. Taps and generator ticks both add to lifetime, which never goes down.

Coming from Unity or another engine

A Godot Resource (.tres) is a ScriptableObject: data you edit in the Inspector and load by path. The catalog is that data. The script only evaluates formulas.

Common pitfalls

  • Storing crumbs with int() looks fine at 15 crumbs and breaks past 2^53. Save with BigFormat.store. Cast only owned counts and total_clicks.
  • Growth typed as 15 makes the second sprout cost ceilf(15 * 15) = 225. The checkpoint price is 18.
  • A shared scene path. Saving the game scene anywhere except res://game/game.tscn leaves the menu loading the empty kit scene.
  • Unique names forgotten. %CrumbLabel errors with "Node not found" when Access as Unique Name is off, even if the node exists.
  • Auto-translate left on for code-built strings turns 0 crumbs into a missing-key lookup. Dynamic labels are Disabled. Static buttons keep the raw key as their Text.
  • Expand on the tap button hides the scroller. Only Lists expands vertically inside Columns.
  • Saving from _notification before _ready finishes would write an empty run over a good file. _ready_done is that guard. Do not remove it.
  • Emitting Events.score_changed with the balance. The argument is an int. Keep crumbs off that signal.

ceilf(15 * 1.15) = ceilf(17.25) = 18. The button shows the ceiled price, not the raw float.

Why is the crumb balance saved as a string from a float, rather than as an int?

  • Godot JSON cannot store numbers at all.
  • JSON numbers are floats, and integers past 2^53 are not exact.
  • SaveManager rejects int values.
  • Floats use less disk than strings, so the string is only for the UI.

The memory value is a float. The file stores text so a later int() cast cannot round the balance. Small counts are still ints, cast on load.

Which call writes the run?

  • SaveManager.save_slot(&"run", payload)
  • Events.score_changed.emit
  • Settings.set_value
  • A new autoload named ClickerSave

The run goes through the Ship Kit SaveManager. High-water lifetime also uses set_value on that same autoload, then flush().

Aspect expand with stretch mode canvas_items means:

  • The picture is cropped to 720×1280 on every phone.
  • Black bars are added and the UI never gains pixels.
  • The renderer switches to Forward+.
  • The base size covers the screen, and extra pixels become extra room that anchors and containers must handle.

That is why the root is Full Rect and the list lives in a container, not at hard-coded coordinates.

Buying 4 sprouts from zero with the bulk formula costs 75, while 15+18+20+23 = 76. What should you ship?

  • Hide the difference by using int prices.
  • Always add ten ceiled unit prices, and delete bulk_cost.
  • Use P(n) for the x1 button and one ceilf on the geometric sum for a multi-buy.
  • Charge 15 forever so the two formulas match.

One ceil on the closed form is the rule in bulk_cost. It can be one crumb under the sum of per-unit ceils. Document it; do not "fix" it with integers.
