Concepts you need first

The loop you are building

A bullet heaven is a top-down survival minute. You move. Weapons fire on their own. Enemies walk straight at you. You pick nothing up yet; that is tomorrow. Today the win condition is "I lasted two minutes and the node count did not climb."

Pools

A pool is a fixed array of nodes created once in _ready. A dead enemy is hidden, moved off-screen, and returned to the free list. instantiate during play is a spike; queue_free during play is another. Forty enemies on screen still means forty-eight enemy nodes the whole run.

Coming from Unity or Unreal?

This is the same idea as an object pool of prefabs or actors. Godot's extra cost is the node and the canvas item behind it, which is why Day 21 stops using a node per enemy. Today the cap is small on purpose so the gameplay code stays easy to read.

Cell hash

A physics area signal per enemy does not scale, and it is the wrong tool when you only need "who is within N pixels." Divide the plane into 64×64 cells. Each frame, clear the buckets and drop each living enemy's id into the cell that contains its position. A query looks at the cells touched by a circle, then you still test real distance. The hash never replaces the distance test; it only cuts the candidate list.

If Retry seems to do nothing

The tree was left paused by the pause menu. hud.gd clears get_tree().paused before reload_current. If you removed that line, reload runs while paused and looks frozen.

Common pitfalls

  • Node count climbs. Something calls instantiate outside _build_pools. Search the scripts. Spawns must pop_back an id from a free list.
  • Shots pass through bats. Game physics priority must be higher than the enemies' so the hash is rebuilt after they move. Priority 20 on Game is later than the default 0. Also confirm you test distance after the hash query. A cell query alone is a square, not a circle.
  • Disabling a shape inside a physics callback. set_deferred is required. Setting disabled directly from _physics_process can error or apply a frame late in a worse way.
  • move_and_slide() with an argument. Godot 4 reads the velocity property. An argument is a Godot 3 call and will not parse.
  • Camera not following. Camera2D must be a child of Player, Enabled on. A second enabled camera elsewhere in the Ship Kit menus is not in this scene, so F6 is clean. If F5 looks wrong only after the fade, you instanced the player under the menu by mistake.
  • Copied project still named Ship Kit. You edited the original folder. The path in the window title bar of File Explorer must be C:\GodotProjects\bullet-heaven.
  • Mask left on the player. If the player mask includes enemies, bodies can block movement even with monitoring off, once you add real physics bodies later. Mask stays empty this game.
  • Parser says a class name is a cycle or is not found. Hud and RunDirector name each other. Save both scripts. If the error stays, in hud.gd type the parent as Node and read values with call: int(get_parent().call("kills")). Do not preload one script from the other.

Check yourself

Why does the swarm come from a pool instead of instantiate plus queue_free each kill?

  • Godot forbids freeing nodes during _physics_process.
  • The node count stays flat and you avoid an allocate-and-free spike every kill.
  • Pooled nodes do not need a position.
  • Only pooled nodes can be added to a group.

queue_free is legal. The point of the pool is the flat cost. Day 21 goes further and removes the enemy node entirely.

A spatial-hash query returns an enemy whose center is 70 px away. Your hit radius is 26 px. What should the code do?

  • Reject it. The hash only lists ids in nearby cells; the circle test is still required.
  • Count it as a hit. The hash is exact.
  • Rebuild the physics space with move_and_slide().
  • Double the cell size until the query is empty.

Cells are squares. Any enemy in a touched cell is a candidate, including ones outside the circle.

Which Camera2D statement matches Godot 4?

  • You must call make_current() or the camera never activates.
  • The property to tick in the Inspector is named Current, as in Godot 3.
  • An enabled camera becomes active when it enters the tree if no camera is active yet.
  • Position smoothing runs only while the game is paused.

enabled defaults to true and claims the viewport when it enters. make_current() exists if you need to switch later. Smoothing is for normal movement.

Why is Game's physics process priority 20 while enemies stay at 0?

  • Higher numbers run first, so the hash is built before enemies move.
  • Lower numbers run first, so enemies move, then the director rebuilds the hash and resolves hits.
  • Priority 20 disables physics on children.
  • It makes move_and_slide() accept a velocity argument.

Node.process_priority (and the physics twin) calls lower values first, ignoring tree order. The director must see this frame's positions.

Read more in the official docs

  • Using CharacterBody2D: velocity and move_and_slide() with no arguments.
  • CharacterBody2D: MOTION_MODE_FLOATING.
  • Camera2D: enabled, position smoothing.
  • Node: process priority (lower runs first) and process mode.
  • Input.get_vector: four actions, length capped at 1.
  • Performance: get_monitor and custom monitors.
