Bullet Heaven II: XP, level-ups, weapons, mobile controls

Bats drop gems. Gems raise a level. A level pauses the run and offers three Resources: a weapon, a passive, or an evolution. A virtual joystick feeds the same move actions as the keyboard, so the player script does not grow a second input path.

Concepts you need first

Resources are the rows

A Resource is a data object you can save as a .tres and edit in the Inspector. It is the row in a table. The script is the column layout. Weapons and passives are rows. Balance is the math that reads those rows plus the player's ranks. Do not also hard-code the same damage number in the spawner.

The XP curve

xp_to_next(level) = round(12 × 1.22^(level − 1)) where level is the level you are now, starting at 1. Bats drop 1 XP. You need 12 XP for level 2.

Slots and evolutions

Three weapon slots, six passive slots. There are exactly three weapons and six passives, so a finished build holds one of each. An evolution is not a fourth weapon. It replaces the weapon in its slot when that weapon is level 8 and the passive named on the resource is rank 5. The level-up screen forces that evolution into the first card.

WeaponPassive requiredEvolutionWhat changes
NeedleQuick Hands (tome) rank 5Storm Needledamage × 1.25, cooldown × 0.55, pierce + 3, projectiles + 2
OrbitIron Will (might) rank 5Nova Ringdamage × 1.40, tick × 0.62, radius × 1.50, orbs + 2
ScatterLong Arms (bracer) rank 5Fan of Knivesdamage × 1.15, cooldown × 0.70, pierce + 1, projectiles become at least 8

Orbit hits each enemy at most once per tick, no matter how many orbs overlap that enemy. Extra orbs widen coverage. They do not multiply single-target damage.

Formulas the code will use

Weapon level L starts at 1. steps = L − 1.

  • Raw damage = base_damage + damage_per_level × steps. Then × (1 + might.amount × might_ranks + 0.04 × shop_might_rank). Then × the evolution damage multiplier if evolved. Shop might is 0 today.
  • Cooldown = max(min_cooldown, base_cooldown + cooldown_per_level × steps) × max(0.45, 1 − tome.amount × tome_ranks) × evolution cooldown multiplier.
  • Projectile count = base_projectiles + floor(steps / extra_projectiles_every), then the evolution projectile rule.
  • Shot speed = projectile_speed × (1 + bracer.amount × bracer_ranks). For Orbit, projectile_speed is radians per second.
  • Move speed = 210 × (1 + stride.amount × stride_ranks) × character_speed. Character speed is 1 today.
  • Magnet radius = 72 + magnet.amount × ranks + shop_magnet.
  • Armor subtracts armor.amount × ranks from incoming contact HP/s. The result is clamped at 0.
  • Bat HP = round(14 × (1 + 0.18 × minute)). Bat speed = min(160, 78 + 3 × minute). Bat contact = 8 + minute HP/s. Minute is int(elapsed / 60).
  • Spawn interval = max(0.04, 0.55 × 0.90^(elapsed / 30)) seconds. The 36-alive cap still applies.

  2. Scene hooks. Open game.tscn. Select World, add a Node2D named Gems and a Node2D named Loadout. Select Game, add a CanvasLayer named LevelUp. Set its Layer to 30. In the Inspector, under Node > Process, set Mode to Always so its buttons work while the tree is paused. Turn Visible off for now; the script turns it on.

WeaponState lives inside Loadout so it is not a global name. The eight orb sprites are created once. Unused ones are hidden. Orbit is the only weapon that moves them.

Block 5: Virtual joystick

Version note

VirtualJoystick is in the class reference this course checked. It is newer than Godot 4.3. Open the Create New Node dialog and search VirtualJoystick. If the node is not in the list, your build does not have it. Skip the property steps and use the fallback script in the details block. Do not invent property names. The Inspector labels below match the class reference: Action Left, Action Right, Action Up, Action Down, Joystick Mode, Visibility Mode, Deadzone Ratio, Joystick Size, Tip Size.

  1. Touch test switch. Menu bar Project > Project Settings > Input Devices > Pointing. Turn on Emulate Touch From Mouse. A mouse drag is then a touch, so you can test the stick on a desktop. Turn it off again before you ship if you want mouse and touch to stay distinct. Day 21's phone build does not need this switch.
  2. Zone. Open game.tscn. Select HUD, add a Control named StickZone. In the Inspector set anchors: Anchor Left 0, Anchor Top 1, Anchor Right 0, Anchor Bottom 1, Offset Left 24, Offset Top -320, Offset Right 324, Offset Bottom -20. That pins a 300×300 box to the bottom-left of the screen. Set Mouse > Filter to Stop.
  3. Joystick node. Select StickZone, press Ctrl+A, add VirtualJoystick, leave the name VirtualJoystick. Anchor preset Full Rect so it fills the zone. In the Inspector set Action Left to move_left, Action Right to move_right, Action Up to move_up, Action Down to move_down. Set Joystick Mode to Following (the enum value JOYSTICK_FOLLOWING). Set Visibility Mode to When Touched (VISIBILITY_WHEN_TOUCHED). Set Deadzone Ratio to 0.18, Joystick Size to 150, Tip Size to 60. Leave the player script alone. Input.get_vector already reads those four actions, and this node presses them.
No VirtualJoystick node? Paste this fallback onto StickZone

Do not also add a VirtualJoystick. Attach res://game/touch_stick.gd to StickZone. It presses the same four actions. Releasing the stick releases those actions, so do not hold WASD at the same time while you test it.

Press F6. Click-drag inside the bottom-left of the window. The player moves with the drag and stops when you release. WASD still works when you are not dragging. During a level-up the tree is paused, so the stick does not slide you around behind the cards. If nothing moves, Emulate Touch From Mouse is off, or the action names on the joystick do not match the Input Map.

Common pitfalls

  • Level-up buttons do nothing. LevelUp must use process mode Always. A pausable layer does not receive clicks while get_tree().paused is true.
  • You emit game_paused from the level-up. The pause menu may open on top of the cards. This day only sets get_tree().paused.
  • Two sources of Needle damage. If you left _fire_needle in game.gd and also tick the loadout, you fire twice and the card numbers lie. The replacement file has no _fire_needle.
  • Evolution never shows. The weapon must already be level 8 and the passive rank 5 before the roll. Ranking the passive on the same card that hits weapon level 8 offers the evolution on the next level, not this one.
  • Gems never arrive. Magnet starts at 72 px. The green icon is small. Walk onto the cluster. If the pool is empty the XP is granted directly and no icon appears; that is intended.
  • CSV shifted a column. A comma inside a translation splits the row. The rows above have none. A broken import shows the wrong language on the cards.
  • Joystick releases WASD. The fallback script calls action_release on all four actions when the finger lifts. The built-in node is the one to ship. Test keyboard and stick separately.

Check yourself

You are level 1 and you have 12 XP. What happens?

  • Nothing. The first threshold is 15.
  • You jump to level 3 because 12 is more than 8.
  • XP becomes 0, level becomes 2, and the card layer pauses the tree.
  • The run ends.

xp_to_next(1) is round(12 × 1.22^0) = 12. One level is spent per open. Leftover XP waits for the next check.

When may Storm Needle appear as a card?

  • As soon as Needle is level 8, even with no passive.
  • When Needle is level 8 and Quick Hands is rank 5, on a later roll.
  • When any passive is rank 1.
  • It replaces the player character.

The resource says Evolve Passive tome. _can_evolve requires weapon level ≥ 8, that passive ≥ 5, and evolved == false. The evolution replaces the weapon; it does not take a new slot.

Why does the joystick not get its own movement code on the player?

  • It presses the existing move_* actions, and Input.get_vector already builds the direction.
  • Touch cannot set velocity.
  • CharacterBody2D reads the screen position on its own.
  • The Mobile renderer moves the body.

One consumer of the Input Map means keyboard, gamepad, and touch stay consistent. The fallback script uses Input.action_press for the same reason.

Why is the level-up layer process mode Always?

  • So gems keep moving during the choice.
  • So move_and_slide() keeps running.
  • Always is the default, and the property does nothing.
  • A paused tree does not process pausable controls, and the buttons must still receive clicks.

Opening the layer sets get_tree().paused = true. Pausable nodes, including the player and the bats, stop. Always nodes keep working.
