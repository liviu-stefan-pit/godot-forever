Concepts you need first

A seed fixes the queue, not the stack

RandomNumberGenerator.seed restarts that object's sequence. Daily mode sets it to the UTC day index int(Time.get_unix_time_from_system() / 86400), then draws tiers with randi_range(0, 4). Restarting daily on the same UTC day draws the same first fruit and the same "next" fruit. Endless calls randomize() instead, which picks a time-based seed.

The stack will not match a friend's phone, and it may not match your own phone after an engine update. Godot's 2D solver is not a lockstep simulation. Do not advertise a global daily leaderboard. The daily best stored here is this device's best for this UTC day, under daily_best plus daily_day. Endless keeps using best_score.

Juice must not consume the gameplay RNG

Shake offsets use the global randf_range. Particles use their own randomness. If either one called _rng.randi_range, the next fruit would depend on how many merges you had, and the "same first two tiers" test would fail as soon as you merged. Pitch is 1.0 + tier * 0.07 on the fruit that appears: cherry (tier 1) is 1.07, melon (tier 7) is 1.49, planet (tier 10) is 1.70. Melon and above also set _shake_left = 0.18.

Do not shake the jar node

Fruits are RigidBody2D children of Jar. Moving Jar every frame teleports the bodies and the solver explodes. The offset is on Camera2D only, for 0.18 seconds, at most 8 pixels.

Press F6. The panel reads Choose a jar, Endless, and Daily (or the Spanish/German words if the locale is already switched). Click Endless. Block 3 continued: prove the daily seed

  1. Start daily. Press F6, choose Daily. Output prints daily seed and a number (the UTC day index, around twenty thousand in 2026) and first tiers: A then B. Write A and B down.
  2. Restart daily. Press F8, then F6, choose Daily again. The seed number matches, and the first two tiers match. Play differently (merge or don't). The first two printed tiers still match, because they are drawn before any shake or particle.
  3. Contrast endless. Start Endless twice. The first-tier pair is allowed to differ. If it is identical every time, _on_endless is setting _rng.seed instead of calling randomize().
  4. Locale. Stop the game. From the kit settings screen set locale es, or temporarily put Settings.set_locale("es") as the first line of _ready, test, then delete that line. The mode button reads Diario. After a merge, Output's fruit name is Uva, Cereza, or another Spanish word, not MERGE_FRUIT_0. If you see the raw key, reimport the CSV.

Two daily starts share a seed and the same first two tiers. Endless is not locked to that pair. A merge log line is translated. If the second daily start differs, something else drew from _rng before _begin (shake must keep using randf_range).

Common pitfalls

  • Seeding and then calling randomize() throws the daily sequence away. Endless is the only caller of randomize().
  • Using _rng for shake or particles changes the next drop whenever a melon merges. The restart test fails even though the seed line matches.
  • Moving Jar to shake flings every sleeping fruit. Offset the camera.
  • One best-score key for both modes lets a daily run overwrite the endless record. Daily writes daily_best and daily_day only.
  • A stale daily_day must zero the displayed best. The check is saved_day == _daily_day before reading daily_best.
  • Pasting game.gd before ModePanel exists errors on %EndlessButton before you can click anything.
  • Seeing MERGE_FRUIT_3 in Output means the CSV was not reimported or the locale has no es/de/en line. English is filled, so a default locale should still say Orange.

Check yourself

Two phones start Daily on the same UTC day. What matches?

  • The entire stack, score, and every bounce.
  • Nothing. Seeds do not work on Android.
  • The drop queue from RandomNumberGenerator. Not the physics result.
  • The score, because gravity is 1600 everywhere.

The seed fixes randi_range on that generator. The solver is not lockstep, so a shared leaderboard would not be fair.

What integer is assigned to _rng.seed in daily mode?

  • int(Time.get_unix_time_from_system() / 86400)
  • The player's best score.
  • Always 0, which means "random".
  • Time.get_ticks_msec()

86400 seconds is one UTC day. The same index lasts until the next UTC midnight. randomize() is endless mode only.

A melon (tier 7) is created by a merge. What pitch does Audio.play_sfx use?

  • 0.07
  • 1.49
  • 7.0
  • 1.0, because pitch is only for the daily mode

1.0 + 7 * 0.07 = 1.49. Planet is 1.70. The tier argument is the fruit that just appeared, not the two that vanished.

Which calls are allowed to consume _rng?

  • Camera shake and the particle burst.
  • Any randf_range in the project, because they share state.
  • The danger-line timer.
  • _roll only, which daily and endless both use for the next tier.

Shake uses global randf_range. Particles keep their own randomness. Drawing a tier anywhere else desyncs the daily preview.
