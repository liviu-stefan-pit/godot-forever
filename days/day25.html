Concepts you need first

Three methods, one preview

Godot asks the control under the pointer for drag data by calling _get_drag_data(at_position). at_position is local to that control. Return null and nothing starts. Return a Dictionary and the drag starts. Call set_drag_preview in that method with a Control that is not in the scene tree. Do not free() the preview and do not keep a variable pointing at it: the engine deletes it when the drag ends.

The control under the cursor at release gets _can_drop_data(at_position, data) first. That method only answers yes or no. _drop_data is where you play the card. The class reference also lists force_drag for starting a drag from code; this game does not need it. A keyboard drag passes Vector2.INF as the position; ignoring the position means that path still returns the same dictionary.

What the card dictionary contains

from_hand (bool), uid (int), target (the CardData.Target enum as an int). Drop zones read those keys. They do not search the hand themselves.

Mouse filter decides who hears the click

The topmost Control with Mouse > Filter set to Stop receives the click. A Label defaults to Stop, so a label on top of the card steals the drag and _get_drag_data on the card never runs. Every child of the card and of the enemy panel is set to Ignore. The root panel stays Stop.

Layout versus containers

An HBoxContainer writes each child's position every layout pass. A hover tween on position loses that fight. The hand is a plain Control that places cards once per rebuild and on resized. Enemy panels stay in an HBoxContainer, so their hit reaction tweens scale and modulate, which a container does not own. Set pivot_offset to half the size or the scale grows from the top-left corner.

Common pitfalls

  • Label eats the drag. Filter Stop on a child means _get_drag_data on the panel never runs. Ignore on children, Stop on the root.
  • Preview added to the card. The preview must not be in the tree. Build it with .new() and pass it only to set_drag_preview.
  • Playing the card inside _can_drop_data. That method is the test. _drop_data emits the uid. A test that spends energy will spend it when the cursor merely enters the panel.
  • Freeing the card during the drop. The hand rebuild is deferred with call_deferred. An immediate queue_free of the source inside _drop_data can upset the drag.
  • Tweening position on an HBoxContainer child. The container puts it back next layout. Enemy hits use scale and modulate. The hand is not a container, so the lift tween on position:y sticks.
  • pivot_offset left at zero. Scale then grows from the corner and the panel slides. punch sets pivot_offset = size * 0.5 first.
  • Unique name missing. %Hand or %Hint errors at ready if Access as Unique Name was skipped. The % must be visible in the Scene dock.

Challenge (optional, 25 min)

Fan the hand

In HandView._layout, after you set position, set pivot_offset to the bottom center of the card (Vector2(CARD_SIZE.x * 0.5, CARD_SIZE.y)) and set rotation from the card's distance to the middle index. Keep the angle small, a few degrees per step. Reset rotation to 0 on the hovered card so the lifted card stays upright.

Hint: do this only in _layout. The lift tween should still own position:y alone. If the fan fights the lift, you are tweening rotation and position in two places.

Check yourself

What does returning null from _get_drag_data do?

  • No drag starts. That is how an unaffordable card refuses the mouse.
  • The last card in the hand is dragged instead.
  • Godot deletes the control that returned null.
  • The drop target receives an empty dictionary.

The Control class reference: return null when there is no data to drag. set_playable(false) makes _get_drag_data return null.

Which preview is valid to pass to set_drag_preview?

  • The card node itself, so the original follows the cursor.
  • A ColorRect you already added under CardView in the scene.
  • A Panel created with Panel.new(), never added to the scene, and not stored in a member variable.
  • A preview you queue_free() at the end of _get_drag_data.

The preview must not be in the tree. The engine frees it when the drag ends. Freeing it yourself, or keeping the reference, fights that.

Defend is dropped on Jaw Worm and the card snaps back. Which method caused the refusal?

  • _drop_data played the card, then undid it.
  • _can_drop_data returned false because the target enum is Self and the enemy zone only accepts Single or All.
  • _get_drag_data returned null, so there was no dictionary.
  • battle.gd deleted the card before the drop.

can_accept compares data["target"] with the zone. A false test means _drop_data is not called and energy is untouched.

Why does the enemy hit tween scale instead of position?

  • Tweens cannot animate position.
  • modulate is deprecated.
  • EnemyRow is a Control with no layout, so position is ignored.
  • EnemyRow is an HBoxContainer. It overwrites child positions. Scale and modulate are left alone.

The hand is a plain Control, so its lift tween may own position:y. The enemy row may not.

A new icon Label is added on top of the card and left at the default mouse filter. Dragging does nothing. Why?

  • The label is Stop, so it receives the click. The card's _get_drag_data never runs.
  • set_drag_preview only works on nodes named Background.
  • Labels cannot be children of a Panel.
  • Unique names disable drag and drop.

_ignore_tree fixes this for children that exist at _ready. A label added at runtime still needs Filter Ignore, or a second pass of that helper.
