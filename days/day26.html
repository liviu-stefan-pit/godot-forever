Concepts you need first

One slot for the run, one key for the record

SaveManager.save_slot(&"run", payload) writes user://saves/run.json. The file on disk is an envelope, format, saved_at, and data. load_slot returns the dictionary you saved, not that envelope. Best floor is not part of the run. It is SaveManager.set_value("deck_best_floor", n) plus flush(), so it survives delete_slot when the run ends.

JSON stores every number as a float. A saved energy of 2 comes back as 2.0. Every counter in _load_run and in Battle.from_dictionary goes through int(). Card ids are strings and stay strings. After RandomNumberGenerator.seed is set, set state second: assigning seed replaces state.

The map is code, the offer is data

Room layout lives in MapCatalog and is not saved. The save stores which ids are cleared, which are open, the pending screen, and any offer you already rolled (three reward cards, shop stock, relic id). Quitting on a shop must not reroll it. Combat saves the dictionary from Battle.to_dictionary() only while it is your turn.

Relic resources are labels. Hooks are code

A relic .tres holds an id and two translation keys. The effect is a hook that already exists, because each relic happens at a different time. Burning Blood heals 6 after a win, in game.gd. The other four run inside Battle.

Common pitfalls

  • Two _ready functions in main_menu.gd. Add the continue lines to the existing function. The parser error names the duplicate.
  • Ints left as floats. Phase becomes unreadable, gold comparisons fail in surprising ways, or available.has(node_id) misses because one side is 0 and the other is 0.0. Cast on load. has on ints is exact.
  • Seed assigned after state. rng.seed = ... wipes state. Restore state second or the next shop rerolls.
  • Clearing the room when you enter a fight. Quit-and-continue would skip the fight. _mark_cleared runs on victory, on leaving the shop, on resting, and when the treasure is granted.
  • Healing Burning Blood on load. The heal is applied once when the fight becomes a reward, then saved. Loading a reward must not heal again.
  • Scanning res:// for relics. Keep RELIC_PATHS. An export that cannot see .tres names still load()s a path you wrote down.
  • Main scene pointed at the map. F5 opens the menu. Continue is a button there, not a second main scene.

Check yourself

A saved fight loads with energy 2.0. What keeps the energy variable an int?

  • SaveManager refuses floats, so this file cannot exist.
  • GDScript turns every JSON float back into an int automatically.
  • int() around each loaded counter in _load_run and Battle.from_dictionary.
  • Storing energy in a Vector2.

The slot is JSON. Numbers come back as floats. The casts are in the load functions, not in the autoload.

Best floor should remain after the run file is deleted. Which call is that?

  • save_slot(&"run", {"best": n}) after delete_slot.
  • set_value("deck_best_floor", n) and flush(), then delete_slot(&"run").
  • Settings.set_volume.
  • A second autoload named Profile.

The run slot is the climb. The profile key is the record. Deleting the slot does not clear set_value data. flush writes the profile now, including when the app is about to close.

Why are relic .tres paths listed in RELIC_PATHS instead of DirAccess.get_files_at("res://data/relics")?

  • An exported project does not list imported .tres files from res:// the way the editor does. load of a known path still works.
  • DirAccess cannot read res:// at all.
  • Resources are not allowed in subfolders.
  • get_files_at randomizes order, which would reroll shops.

The class reference for get_files_at says exported res:// listings are .gd, .import, and similar, plus .remap names depending on the text-to-binary export setting. A written path avoids that.

You quit on the shop, then Continue. The three cards are different. What failed?

  • Anchor cleared the shop.
  • JSON cannot store strings.
  • Array.shuffle was seeded, so this is expected.
  • The offer was rolled again on load instead of reading shop_cards and shop_relic from the slot.

The map is code and can be rebuilt. The offer is random, so it is stored. Load shows that stock. The next roll uses the saved RNG state only when something new is generated.

Anchor says +10 Block at the start of combat. Your Block line is 0 on turn 1. Which order matches the code you shipped?

  • Add Anchor's Block, then set Block to 0 because the turn started.
  • Set Block to 0, then, on turn 1 only, add 10 if the relic id is present.
  • Add 10 Block at the end of the enemy turn so the player never sees it.
  • Anchor replaces energy, not Block.

_begin_player_turn clears Block first. Anchor runs after that clear, and only when turn_number is 1. The next turn clears it again, which is what you want: the Block existed for the first enemy phase.
