Concepts you need first

Prices are a formula, not a feeling

Going from level L to L + 1 costs base * (L + 1) * (L + 1). Ten copper is 10 * 8 = 80 credits, which is exactly the first fuel tank. Five iron is 90, the first cargo bay. The hull fails by losing cargo and popping back to the shaft; credits and upgrades stay. That is the extraction loss.

Streaming keeps the dug set, not the pixels

A chunk outside the 5×5 window is erased with erase_cell. The _dug dictionary is not cleared. The next load_chunk skips those coordinates, so the hole is still a hole. If you erase the dictionary too, the cave grows back.

JSON numbers come back as floats

SaveManager.save_slot writes the dictionary you pass (the file wrapper adds format and saved_at). On load, every number is a float. Credits, upgrade levels, and cell coordinates go through int(). Fuel and hull stay floats. Vectors are stored as [x, y].

What the kit already does

SaveManager.flush() is already called on window close, app pause, and focus-out for the small profile. The run slot is ours, so game.gd also saves that slot on those notifications. set_value("best_depth", n) is the profile high-score, separate from the slot.

Block 3 continued: strings, then play the loop

  1. Append translation rows. Open res://i18n/translations.csv. Leave yesterday's DIGGER_ rows. Paste these at the bottom. fr, pt_BR, ru, and zh_CN stay English on purpose. Save.
  2. Play a first loop. Press F6. Read the tutorial line. Dig until cargo is at least 1. Go deeper than 8, then return until Depth is 0. Press E. The shop lists the six upgrades and a sell total.
  3. Buy the tank. Ten copper (or any mix that quotes at least 80) then Sell, then Fuel tank. The button must change from Lv 0 of 5 for 80 cr to Lv 1 of 5 for 320 cr, and the fuel max becomes 140. Close the shop. Fuel refills toward 140 while you sit on the surface.
  4. Find a hazard. Dig past depth 18 along a cave edge for yellow-green gas, and past depth 30 for red magma. Gas triples the fuel drop only while you thrust. Magma drops the hull bar. Standing in magma at hull 0 clears cargo, toasts Hull failed, and puts you back in the shaft. Credits stay.
  5. Reload. Note the seed number in Output. Dig a side pocket you will recognize. Wait 8 seconds or press E at the surface and Close (both save). Press F8, then F6. The same seed prints. The pocket is still empty. Cargo and the tank level match what you left. Output's second line is the user-data folder; saves\run.json is the slot.

A second F6 restores the hole, the credits, and the upgrade level. If credits reset to 0 but the seed matches, save_slot did not write the run fields: load_slot returns that dictionary, not the on-disk format / data envelope. If the seed changes every launch, has_slot is false: confirm saves/run.json exists in the printed folder. If the shop buttons error with Node not found, a unique name is missing the % flag.

To throw the run away and keep the project, delete run.json in that folder. best_depth is the profile key, not the slot, so it can outlive the file.

String format errors

If Output says the string had nothing to format, a DIGGER_ row did not reimport and tr() returned the raw key. Save the CSV, click it in the FileSystem dock, and confirm the Import dock lists it as a translation. Then run again.

Common pitfalls

  • Forgetting int() on upgrade levels. JSON returns 1.0. 1.0 + 1 becomes a float and the next cost is wrong. _load_int_dict is the cast.
  • Unloading _dug with the chunk. The cave refills when you fly back. unload_chunk only calls erase_cell.
  • Collision rectangles on columns 6 and 7. Magma becomes a wall you cannot enter, so the 18-per-second damage never runs. Remove those polygons in the TileSet panel.
  • Shop and pause together. The shop does not pause the tree. Escape still pauses. Unpause with the pause menu, then press Close. The pause instance's layer is 20 so it draws above the shop.
  • Saving a Vector2. The slot stores [x, y]. Putting global_position in the dictionary does not survive JSON.
  • Edited save_manager.gd. Slot name is run. Profile keys are best_depth and best_credits. That is the whole API this game uses.

Check yourself

You saved credits = 80. On the next launch the value is a float. What do you do?

  • Store credits only in a String and never use JSON.
  • Call float() and compare with == against the int 80.
  • Assign credits = int(loaded.get("credits", 0)).
  • Turn off the SaveManager format version.

JSON has one number type. Counters, levels, and cell coordinates are cast with int(). Fuel and hull are real quantities and stay floats.

The fuel tank is level 1. What is the credit cost of the next purchase?

  • 80
  • 160
  • 320
  • 400

Cost is base * (level + 1)². Base 80 at level 1 is 80 * 4 = 320. The first purchase, from level 0, was 80.

A chunk scrolls off and unload_chunk runs. What must remain true?

  • The dug dictionary is cleared so the next load is faster.
  • Painted cells are erased, and _dug still lists the holes.
  • The whole TileMapLayer node is freed.
  • The seed changes so the chunk cannot collide with the old one.

load_chunk skips coordinates in _dug. Clearing that dictionary regrows the mine on top of the player.

Hull reaches 0 in magma. What does the player keep?

  • Cargo, credits, and the current coordinates.
  • Nothing. The slot is deleted.
  • Cargo only.
  • Credits and upgrades. Cargo is cleared and the drill returns to the shaft.

damage_hull zeros cargo, sets fuel to 20% of max and hull to 35% of max, moves the drill to cell (0, 1), emits Events.game_over, and saves.

Which SaveManager call stores the dug cells?

  • save_slot(&"run", data)
  • set_value("dug", data) only
  • Settings.set_value("run", data)
  • SceneRouter.go_to

The slot is the run. set_value is the small profile (best_depth, best_credits). Settings stores volume and locale, not the mine.
