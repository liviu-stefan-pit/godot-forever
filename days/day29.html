Concepts you need first

Steam does not open your Godot project. It installs a folder: an exe, a pack, and the license file beside them. Godot's job ends at --export-release. Everything after that is Steamworks. Those pages are not in the Godot documentation, so every one of them sits in an external callout. If a button name below does not match the site, search the phrase and follow the site.

GodotSteam is the same kind of dependency. It is a GDExtension people add so the game can call Steam. The engine class reference has no Steam singleton. Treat every method on it as external, and read the reference that came with the addon version you installed.

The flag

Exporting projects and the command line tutorial both use --export-release. --export-debug is the other switch. Store uploads use release.

Release build from PowerShell

Click "Mark done" on a step to track where you stopped.

  1. Confirm the preset name. Open the game project. Project > Export.... The Windows row must be named Windows Desktop. If you renamed it, either rename it back or use your name in the command below. The string on the command line is matched exactly.
  2. Confirm the export path. Select that preset. The path at the bottom should be an exe outside res://. For the template that is C:\GodotProjects\ship-kit-build\windows\ShipKit.exe. A copied game uses its own folder, for example C:\GodotProjects\idle-clicker-build\windows\IdleClicker.exe. The steps are the same.
  3. Close the game if it is running. An exe that is open cannot be overwritten. Press F8 in the editor too, so the editor is not locking the pack.
  4. Run the export. Open PowerShell. Replace the Godot path with yours. The & is PowerShell's call operator.
  5. Read the log. The window should end without an error about missing templates. If it says the preset was not found, the name does not match, including spaces. If it says templates are missing, go back to Editor > Manage Export Templates... and install the pack for this editor.
  6. Add the license file. Copy res://licenses/GODOT_COPYRIGHT.txt into the same folder as the exe. If you have not saved that file yet, follow Licenses and credits first. The export does not copy it for you.
  7. Smoke-test the exe. Double-click it. Main menu, one run, pause, quit. This is not a Steam launch. It only proves the export is a release player.

The build folder contains the exe and GODOT_COPYRIGHT.txt. The exe is not named Godot and it does not open the editor. Output from the PowerShell command does not contain "Export With Debug" as the mode you selected. You used --export-release.

Steamworks app and store assets

External resource

Verify every click on partner.steamgames.com. The steps change. Search is more reliable than a memorized menu.

  1. Sign in. Open the partner site with the Steam user that owns the games. Finish any identity prompt the site still shows. If the account is not in good standing, stop. An upload will fail later for a reason that looks like a Godot bug and is not.
  2. Read the fee. Search the partner site for the fee charged when you add an app. Pay it only if you want an app id today. Write down the amount you were actually charged.
  3. Create the application. Search "create application" or "new app". Name it the store name, not ship-kit, unless you are only practicing. Copy the numeric app id into a note. You will paste it into SteamCMD and, if you add GodotSteam, into steam_appid.txt.
  4. Create a Windows depot. Search "depots". Add a depot for Windows 64-bit. Copy the depot id. Leave macOS and Linux depots out until you export those platforms. This course's upload is the Windows folder from the previous section.
  5. Open the store graphical-asset checklist. Search "graphical assets" or "store page". The page lists capsules, a header, library art, and screenshots. Write down the pixel sizes it shows today. Ignore sizes you remember from an older article.
  6. Capture screenshots from the release exe. Run the exe, not the editor. On Windows, Win+Shift+S grabs a region. Crop to the size the checklist asks for. Five screenshots of the real menu and the real game are enough to start. Do not upload the Godot editor.
  7. Fill the text fields the checklist requires. Short description and about-this-game text. Mention only languages you actually filled in translations.csv, and only controller support you have tested.

You have an app id, a depot id, and a note of the current capsule sizes. The store page is a draft. It is not public. If the site will not let you create an app, the block is the partner account, not the exe.

SteamCMD upload

External resource

Search "SteamCMD" and "SteamPipe" on partner.steamgames.com. Install the tool the way that page says. The script shape below matches the samples those pages have used. Diff it against the sample you see today before you run it. Replace the zeros with your app id and depot id.

After app_build.vdf has your ids, the upload is two SteamCMD commands on one line: +login and +run_app_build. SteamCMD asks for the password and any Steam Guard code. Do not paste the password into a file. Diff these flags against the partner sample you see today.

  1. Install SteamCMD into C:\GodotProjects\steamcmd using the partner instructions. Do not put it inside a Godot project.
  2. Write a build script next to it, C:\GodotProjects\steamcmd\app_build.vdf. A starting point:
  3. Set the two ids. Replace both 0 values. ContentRoot must be the folder you listed in the checkpoint, the one with the exe. Double the backslashes inside this file. SteamCMD's parser treats a single backslash as an escape.
  4. Log in and upload. Run the PowerShell line in the external callout above. Replace yourname with your partner login. SteamCMD asks for the password. If it asks for a Steam Guard code, that is expected. Do not paste your password into a script file in the Godot project.
  5. Set the build on a beta branch first. Search "branches" in Steamworks. Put this build on a passworded beta, not on default. Install the beta in the Steam client. Launch from Steam. Play the menu. Then, and only then, consider default.

SteamCMD's log says the depot was built. The Steam client's beta branch launches your menu. Double-clicking the exe and launching from Steam both work. If Steam launches a black window, the depot's content root was the project folder or an old debug export. Fix the VDF and upload again. Builds are cheap. A public default branch is not.

GodotSteam achievements

External resource

Create the achievement in Steamworks first (search "achievements"). The API name, such as ACH_WIN, is the string the addon will send. Then install a GodotSteam build that matches your Godot version. Its class reference is the method list. The sketch below is the shape people use. If steamInit or setAchievement is named differently in your addon, use the addon. Do not file an engine bug.

  1. Define one achievement on the partner site. Copy its API name exactly.
  2. Add the addon the way its own readme says. Enable the plugin under Project > Project Settings > Plugins if the readme says to.
  3. Editor app id. If the addon docs tell you to drop steam_appid.txt in the project root containing only the app id, do that for editor runs. Keep it out of marketing screenshots.
  4. One listener, not ten. Add a script that connects to Events.achievement_unlocked and calls the addon. Games only emit the signal. A sketch you must edit to match the addon:
  5. Do not register this as a required kit autoload unless that game ships on Steam. The five names stay Events, Settings, SaveManager, Audio, SceneRouter. If you add this sixth autoload, name the node something like SteamAchievements and put it after Events so the signal exists.
  6. Trigger it once from the game with Events.achievement_unlocked.emit(&"ACH_WIN") using your real API name. Run from the Steam client, not only from the editor. The partner site's stats page, or the overlay, should show the unlock. Editor runs need Steam running and the app id file.
If the script does not parse

A parse error on Steam means the addon is not installed or not enabled. Delete this file until it is. The rest of the Ship Kit must still run.

Controller and Steam Deck

  1. Plug in a controller. Run the release exe. The main menu's Play button should show a focus rectangle after you press a direction or the south face button. If nothing focuses, grab_focus() on the menu did not run. That is a Godot bug in the scene, fixed in main_menu.gd, not a Steam bug.
  2. Play and pause from the pad. pause is Escape and, if you bound it, Start. The pause menu is process_mode Always. Resume must work with ui_accept.
  3. Read the Deck checklist as external. On the partner site, search "Steam Deck". Check text size, a 16:10 window, and full controller play against the list you see. Your project already uses stretch mode canvas_items and aspect expand, so a wider window adds space instead of bars. Resize the release exe's window to something near 1280×800 and look for buttons under the edge.
  4. Do not tick Verified yourself in the store text. Deck review is Steam's. You can write "controller supported" only after the pad test above passed.

A gamepad reaches Play, moves the game if the game uses move_*, and pauses. The partner site has a draft store page and a beta build you have launched from the Steam client. GodotSteam, if you added it, parses, and one achievement unlocks from a Steam launch. If you skipped the addon, the five kit autoloads still run and you have not left a broken Steam reference in the project.

When the upload looks like a Godot bug

Most failed Steam uploads are a wrong folder or a wrong id. Walk this list before you change a script.

What you seeWhat it usually is
SteamCMD says the app id is invalidThe VDF still has 0, or the app is not in good standing yet. The fee and the identity check are on the partner site.
The build succeeds and the Steam client launches nothingContentRoot pointed at res:// or at an empty directory. Open the depot in Steamworks and look at the file list. You want the exe at the root of the depot, not nested in ship-kit-build\windows\windows.
The client launches the Godot splash and then a debuggerYou uploaded --export-debug, or you uploaded Godot.exe itself. Re-export with --export-release.
The menu opens and then an error about a missing autoloadThe export did not include a script because of a parse error. Run the exe from PowerShell so the console build prints it. Fix the script. Do not "fix" it by deleting SaveManager.
Achievements stay locked in the overlayThe API name does not match Steamworks, storeStats was not called, or you only ran from the editor without Steam. This is the addon, not Events.
A controller does nothing on the menugrab_focus() never ran, or you deleted ui_up / ui_accept. Those rows are engine input, documented with the focus tutorial. Steam Input glyphs are a partner-site topic. Search "Steam Input" there if you want Steam's glyph set. The game does not need that set to be playable.

Keep the five kit autoloads spelled the way Day 15 registered them. A Steam upload does not get its own save_game() or a renamed SceneRouter. The beta branch should boot the same main menu F5 boots.

External resource

Depot file lists, branch passwords, and review times are on partner.steamgames.com. Search "builds" and "SteamPipe". If the site's sample VDF uses different key capitalization than the sample in this lesson, follow the site. The tool is theirs.

Common pitfalls

  • Uploading the Godot project folder. Steam needs the export folder. project.godot in a depot is a mistake.
  • --export-debug on a store branch. Use --export-release.
  • Preset name mismatch. Windows is not Windows Desktop unless you renamed the preset.
  • Single backslashes in the VDF. The content root silently points at the wrong place.
  • Setting default live before the Steam client launch. You cannot un-see a bad push on a public branch as easily as you can delete a beta.
  • Calling GodotSteam from gameplay scripts everywhere. One listener on Events.achievement_unlocked keeps the game runnable without the addon.
  • Capsule pixels from memory. The partner checklist is the size list.

Challenge (optional, 20-30 min)

A second depot branch without touching default

Change one label in the main menu, export again, upload again, and install the new beta build from Steam. Hint: bump the Desc string in the VDF so the build list shows which upload is which. Do not move the default branch. Confirm the Steam client is running the new label, then quit.

Check yourself

Which command flag does the Godot export docs use for a store build?

  • --export-debug
  • --export with the editor still in debug mode
  • --export-release
  • --export-pack only

The exporting page and the command line tutorial both document --export-release. The preset name is a separate argument and must match the Export dialog.

Where do Steamworks steps live?

  • On partner.steamgames.com, and they change. They are not in the Godot docs.
  • In Project Settings, under Steam
  • In SceneRouter.go_to
  • Inside default_bus_layout.tres

Depots, capsules, fees, and SteamCMD are external. Godot's piece is the Windows release export plus the controller actions you already mapped.

What should ContentRoot point at?

  • res://
  • The folder that contains the exported exe
  • The Godot editor install
  • user://saves

Steam installs files. It does not open a Godot project. The export folder plus GODOT_COPYRIGHT.txt is the upload.

How should gameplay code unlock a Steam achievement?

  • Call a Steam method from every script that might unlock something
  • Write the achievement into user://settings.cfg only
  • Rename the Events autoload to Steam
  • Emit Events.achievement_unlocked, and let one addon listener call GodotSteam

GodotSteam is optional and external. The signal is part of the kit. Games that are not on Steam never reference the addon.

What is the Godot-side Deck check you can do without Steam's review?

  • Mark the store page Verified
  • Switch the renderer to Forward+ and hope
  • Resize the release window, confirm canvas_items / expand, and play with a controller only
  • Delete the ui_* input actions

Focus and the stretch mode are engine features. The Verified label is Steam's process, documented on the partner site, not a checkbox in Godot.
