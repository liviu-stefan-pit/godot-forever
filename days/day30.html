Concepts you need first

Play App Signing splits two keys. The app signing key is what players' phones use to recognize an update. Google can hold that key. The upload key is what you use to sign the AAB you send them. In this course the Godot release keystore is that upload key. You still back it up. Enrolling in Play App Signing does not make the keystore disposable.

Target API is a Play rule that moves every year, written into the preset as gradle_build/target_sdk. The Godot field is real. The number you type is whatever the console requires this month. Version code is an integer that only goes up. The visible version string is a different field. Players see the string. Play rejects a code that is not higher than the last upload.

Version note

Godot 4.8 and later can install the JDK and Android SDK from the editor. The export page's manual section is for older 4.x. Match the docs site's version selector to your editor before you copy an SDK install command. The AAB requirement itself is older: new apps after August 2021.

Preset, target API, version code

Click "Mark done" on a step to track where you stopped.

  1. Open the Android preset. Project > Export.... Select Android. Confirm Gradle Build > Use Gradle Build is on and Export Format is the aab option.
  2. Read the target API from Play, then type it. This number is not in the Godot docs as a permanent value. In the console, search "target API". Note the level they require for new releases. Back in the preset, set Gradle Build > Target SDK to that level. The class reference calls the property gradle_build/target_sdk. If Min SDK is lower than Target SDK, leave Min SDK at the default unless the console also names a minimum you fail.
  3. Bump the version code. Find Version > Code (version/code). If this package has never been uploaded, 1 is fine. If it has, add 1 to the highest code Play has accepted. The version name string can stay 1.0.0 or match your notes. The code is the one that must increase.
  4. Confirm the package name. Package > Unique Name is com.yourname.yourgame with your real segments, all lowercase. The template's com.yourname.shipkit is only for the template. A copied game uses the name from the course game page (idleclicker, bulletheaven, physicsmerge, deckbuilder, deepdigger).
  5. Confirm the release keystore. Release path, Release User shipkit or the alias you chose, Release Password. Debug keystore fields stay empty of your release password. You are not shipping the debug key.
  6. Edge to edge stays on. Screen > Edge To Edge enabled, Immersive Mode off, unless this game's design hides the bars on purpose. safe_area.gd pads from DisplayServer.get_display_safe_area.
  7. Export. Path C:\GodotProjects\ship-kit-build\android\ship-kit.aab, or the matching folder for the copied game. Click Export Project.... Uncheck Export With Debug. Save. Wait for Gradle.

A new .aab exists. The export log does not say debug. Version code is the number you intended. If Gradle says the passwords do not match, the keystore was created with two different passwords. Recreate it with one password at both keytool prompts, and do that only if this keystore has never been used for an upload.

keytool, from the Android export page

JDK 17. Same password twice. Letters and digits. The docs page is Exporting for Android.

App Signing, data safety, rating, listing

External resource

These forms are on play.google.com/console. Search the words in each step. If the button moved, the search result is the step. Do not follow a blog's click path from a previous year.

  1. Create the app in the console if you have not. The package name must match Unique Name exactly. You cannot change it later.
  2. Play App Signing. Search "App Signing". Enroll. Understand the sentence on that page that says Google holds the app signing key and you keep the upload key. Your Godot release keystore is the upload key. Download any certificate the page offers and store it next to the keystore backup, outside res://.
  3. Upload the AAB to an internal testing track first. Search "internal testing". Upload the file you just exported. If the console rejects the target SDK, go back to the preset, set the level it names, bump the version code, export again. If it rejects the signature, you used the debug keystore or Export With Debug was on.
  4. Data safety. Search "data safety". For an unmodified Ship Kit, saves and settings stay on the device in user://. You do not send them to a server. Say that, if it is still true of this game. If the game has no account and no ads, do not claim you collect advertising identifiers. Submit the form.
  5. Content rating. Search "content rating". Answer the questionnaire for this game. A deckbuilder and a digger do not get the same answers. Wait until the rating is issued. Production stays blocked without it.
  6. Store listing. Search "main store listing". Fill the title, short description, and full description. Add the icon and screenshots at the pixel sizes the form shows today. Capture them from a phone or from the release window, not from the Godot editor. Mention languages you actually ship in the CSV.
  7. Privacy policy URL if the form requires one. A game that only stores local saves often still needs a URL because the console asks. Host a page you control. Do not invent a policy that claims you collect nothing if you enabled ads.

Internal testing has the AAB. Data safety is submitted. The content rating questionnaire is complete or waiting on their email. The listing shows your icon, not the default Godot robot, unless you chose that icon on purpose. Nothing in the description mentions a feature the build lacks.

Tracks and the closed test

External resource

New personal Play accounts have been required to run a closed test before production: 12 testers opted in, for 14 consecutive days. Google has changed that count. On the console, search "closed testing" and follow the requirement printed there. The fee to open the developer account is also listed on the signup page. Confirm both before you rely on this paragraph.

  1. Internal track is you and the emails you list. Install from the opt-in link on a phone. Cold-start, play, pause, background the app for a minute, reopen it. SaveManager.flush should have run on NOTIFICATION_APPLICATION_PAUSED. Kill the app from the recents screen and reopen. Progress you flushed is still there.
  2. Closed testing is the track that starts the clock for a new personal account. Add testers the way the console describes. Tell them the opt-in link. The clock starts when the console says it starts, which is usually when enough testers are opted in, not when you click upload.
  3. Do not upload a debug AAB to that track. Export With Debug off. A tester crash on a debug build wastes the 14 days.
  4. Open testing and production come after the closed-test requirement is marked done in the console. Production uses a higher version code than the closed track if you changed anything.
  5. Write the date you started the closed test and the tester count the console asked for, in the same note as the keystore location.

A phone that is not your editor machine installed the game from Play's testing link. Backgrounding did not wipe the save. The console shows the closed test as active, or it shows a specific unmet requirement you can name. "I think it uploaded" is not the checkpoint.

Billing and ads, optional

  1. Leave both off if the game is paid up front or free with no items. The Ship Kit does not reference either SDK. That is a valid launch.
  2. Billing, if you need it. Read Android in-app purchases. The plugin name is GodotGooglePlayBilling. Install from the instructions on that page. The plugin's own manual is linked from there and is not the engine class reference. Re-read it when you upgrade Godot. Create products in the console before the game tries to buy them.
  3. Ads, if you need them. They are not in the Godot docs. Treat the whole integration as external. Policy and SDK setup are on play.google.com/console. Search "ads". Then redo data safety. Do not add an ad SDK to a game you described as collecting nothing.
  4. Symbols. If a tester gets a native crash, the docs page Resolving crashes on Android covers uploading symbols to Play. Do that before you guess.

Walk the checklist

  1. Open the launch checklist. It is three lists: both stores, Steam, Play.
  2. Tick Both stores against this AAB and, if you did Day 29, against the Steam beta. A failed box stops the upload. Fix and export again. Do not edit the store text to hide it.
  3. Tick the Play section only for items the console shows as complete. Target API, version code, data safety, rating, listing, and the closed-test rule are the usual blockers.
  4. Tick Steam only if Day 29's beta actually launched from the Steam client. Otherwise leave those boxes empty. An empty Steam section does not block Play, and the reverse is also true.
  5. Stop when a box is no. The automatic no-go lines on that page are: debug export, missing license text, crash on launch, Android save lost on pause, a missing keystore, or a store page that promises something the build does not do.

You can point at the checklist and say which boxes are yes. The AAB on the testing track is the file you just exported. Credits still open and show the engine license. You know where the keystore file is.

Rejection emails and the "publishing overview" checklist are on play.google.com/console. Search the error string. The closed-test gate for a new personal account is there too. Common pitfalls

  • Reusing com.yourname.shipkit for two games. Play treats that as one app. Change Unique Name when you copy the template.
  • Version code unchanged. The second upload is rejected. Bump version/code every export you upload.
  • Target SDK from a blog. The console is the number. The Godot field is only where you type it.
  • Export With Debug checked on the file you dragged into the console.
  • Two passwords in keytool. Godot needs them equal.
  • Data safety filled in before you added ads. The form is part of the build. Update it when the build changes.
  • Starting the 14-day test on a crashy build. Testers opt in, the build crashes, the clock still ran. Internal-test first.
  • Assuming Play App Signing means you can delete the keystore. That file is the upload key. Keep it.

Challenge (optional, 20-30 min)

Prove flush on a real pause

On the internal-test build, earn a SaveManager.set_value("best_score", n) you can see, call flush(), background the app, force-stop it from Android settings, and reopen. Hint: the profile file is user://profile.json. If the score resets, flush did not run on NOTIFICATION_APPLICATION_PAUSED. That notification is already in save_manager.gd. Check you did not replace the kit script with a shorter one in the copied game.

Check yourself

After you enroll in Play App Signing, what is the Godot release keystore?

  • Useless. Delete it.
  • The upload key. Back it up. Google holds the app signing key.
  • The same file as the debug keystore
  • A Steam depot

Play App Signing is a console feature, not a Godot feature. You still sign the AAB with the release keystore before upload. Losing that file blocks updates.

Where do you read the target API level you must set?

  • It is hard-coded in SceneRouter
  • Any blog from the year you learned Android
  • Play Console, the current target API requirement, then typed into gradle_build/target_sdk
  • The Master audio bus

The Godot property exists. The number changes on Google's schedule. The console page is the source.

What does version code have to do on the next upload?

  • Increase. Play rejects a code that is not higher than the last accepted build.
  • Stay at 1 forever
  • Match the viewport width
  • Equal the keystore password

version/code is an integer in the Android preset. The player-facing version name is a different field.

Which closed-test statement matches this course?

  • Production is immediate for every new personal account
  • The tester count is a Godot project setting
  • You must use ads to finish the test
  • New personal accounts have faced a closed test (taught here as 12 testers for 14 days). Confirm the current rule on the console because it has changed.

That rule is Play policy, external, and it has moved before. The console text wins over this page.

When are ads part of the Ship Kit?

  • Always. The template loads them in Audio.
  • Never by default. They are an optional external SDK, and they change the data safety form.
  • They are a button in Project Settings, Rendering
  • They replace SaveManager.flush

Billing has an official Godot docs page and a named plugin. Ads do not. Both are optional. A game that does not show them should not request them.

What copied games are not allowed to rename

Idle clicker, bullet heaven, physics merge, deckbuilder, and deep digger start as a copy of C:\GodotProjects\ship-kit. They change the window size, the package name, and the files under res://game. They do not change the kit. If a later day calls a method that is not on this list, the day is wrong, not the kit.

  • Events: game_started, game_paused, game_over, score_changed, achievement_unlocked, settings_changed, toast_requested.
  • Settings: get_volume, set_volume, is_fullscreen, set_fullscreen, get_locale, set_locale, get_value, set_value, save_settings, save_input_map, load_input_map.
  • SaveManager: FORMAT_VERSION, has_slot, save_slot, load_slot, delete_slot, get_value, set_value, flush.
  • Audio: play_sfx, play_sfx_varied, play_music, stop_music.
  • SceneRouter: MAIN_MENU_SCENE, GAME_SCENE, transition_finished, go_to, reload_current, quit_game.

Pause stays ShipPauseMenu.toggle() on a CanvasLayer whose process mode is Always. Buses stay Master, Music, SFX. Translation columns stay keys,en,es,de,fr,pt_BR,ru,zh_CN, and new game strings use that game's prefix. Cast JSON integers with int() when you read them back. The full scripts are on the Ship Kit page.
