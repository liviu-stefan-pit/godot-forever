Arcade Dodger

A portrait dodge game in the shape of the official "Dodge the Creeps!" tutorial. You steer a character around a 480×720 field, survive as long as you can, and the creeps get faster. The project is C:\GodotProjects\g01-dodger. Days 3 and 4 are the build; this page is the design you are aiming at.

Built on Days 3–4Area2D, RigidBody2D, CanvasLayer, GPUParticles2D

Game design

One screen, no levels. The player starts near the bottom center. Creeps spawn on the edges and fly inward. Every second alive is one point. Touching a creep ends the run. There is no win: the difficulty ramp caps, and the longest life is the score that matters.

What the player gets
MoveActions move_left, move_right, move_up, move_down. Each has an arrow key and WASD. Input.get_vector keeps diagonals at the same speed. Position is clamped to the 480×720 screen.
StartThe Start button, or Enter via the start_game action on that button's shortcut.
PauseEsc, the built-in action ui_cancel. Only while a round is running. Second press resumes.
LoseA mob overlaps the player. The player hides, the screen shakes, music stops, the death sound plays, then "Game Over" or "New best!".
Score+1 per second from ScoreTimer. Every 5 points is one level: spawn wait drops by 0.03 s (floor 0.20 s) and mob speed gains 12 px/s (cap +150). Player speed stays 400 px/s, so at the cap the fastest creeps match the player.
BestSaved at the moment it changes, shown on the title screen, cleared only after a two-click confirm.

Keyboard is the required control set. Gamepad and touch are stretch goals. The window is portrait on purpose (the same 480×720, canvas_items, keep setup as the official tutorial), with the Mobile renderer so later 2D games match it.

Scope: what "done" means

Training-game minimum. When every line is true in g01-dodger, Dodger is finished. Day 4's wrap-up is this list, played and exported.

  • Project g01-dodger, Mobile renderer, viewport 480×720, stretch mode canvas_items, aspect keep, main scene main.tscn.
  • Player is an Area2D on layer 2 (player) with mask 3 (enemies), moves with the four move_* actions, and clamps to the screen.
  • Walk and up animations play only while moving, and the sprite flips with direction.
  • Mobs are RigidBody2D on layer 3 with no mask and gravity scale 0. Each picks fly, swim, or walk at random.
  • Mobs spawn on a clockwise MobPath, fly inward, and queue_free when VisibleOnScreenNotifier2D fires screen_exited.
  • The first overlap ends the run: body_entered emits hit, and the collision shape is disabled with set_deferred.
  • Score increases by 1 per second. The HUD shows it with a short scale pop.
  • HUD is a CanvasLayer (process mode Always): score, best, message, Start, and Reset best score, using game_theme.tres and Xolonium.
  • Start (button or Enter) hides the buttons, shows "Get Ready", and a restart clears every node in the mobs group.
  • Game over shows "Game Over" or "New best!", then the title and the buttons return.
  • Juice: message tweens, a GPUParticles2D trail while the player moves, camera shake on death, looping music, and a death sound.
  • Difficulty ramp matches the table in Day 4 (wait floor 0.20 s, speed bonus cap +150).
  • Best score is stored with ConfigFile at user://dodger.cfg by the HighScore class (static functions, not an autoload) and survives an exported exe.
  • Esc pauses and resumes during a round. A Windows Desktop release export (Dodger.exe plus Dodger.pck, Export With Debug off) runs from Explorer.

Architecture

Main calls down into the player, the HUD, and the timers. The player and the HUD never call Main; they emit signals. HighScore is class_name HighScore on a RefCounted script with static func only. Nothing is registered under Project Settings > Globals > Autoload.

Player

Player (Area2D)                 [player.gd]   class_name Player
├── AnimatedSprite2D            scale 0.5; animations walk, up
├── CollisionShape2D            CapsuleShape2D
└── Trail (GPUParticles2D)      emitting only while moving; Z Index -1

Who owns what

PieceResponsibility
player.gdRead move actions, animate, emit hit, toggle Trail.emitting. Exposes start(pos).
mob.gdPick an animation in _ready. Free itself off-screen. Velocity is set by Main before add_child.
hud.gdScore, best, messages, pause. Signals start_game and reset_best_requested. No reference to mobs or Main.
main.gdSpawn along MobPath, score, difficulty, shake Camera2D.offset, music, call HighScore.
high_score.gdload_best, save_best, reset. File user://dodger.cfg, section scores, key best.

Where you build it

  • Day 3: create g01-dodger, import the zip, player, mobs, the spawn path, and a playable loop without a HUD.
  • Day 4: HUD, theme, juice, difficulty, HighScore, pause, portrait check, and the Windows export.

Stretch goals

  • On-screen pause button (the Day 4 challenge) and a touch pad that feeds the same move_* actions.
  • Gamepad: bind a stick and buttons to the existing actions. No script changes if you only use the Input Map.
  • A one-file build with Binary Format > Embed Pck ticked, then zip that exe alone.
  • A credits label on the title screen using the lines in Assets and credits, including fonts/LICENSE.txt for Xolonium.
  • Two more feelings, still on these scenes: a brief color flash on hit, and a pitch change on DeathSound via pitch_scale.
