Publishing

Launch checklist

Go means every box in the matching store section is checked on the build you are about to upload. A no on any box in "Both stores" stops the upload. Store-only boxes stop that store only. Tick them on the candidate build, not on yesterday's export.

Windows releaseSigned AAB

Both stores

  • The export used --export-release or the Export Project button with Export With Debug unchecked.
  • The game boots to the main menu, starts a run, pauses, opens settings, and quits without a red error in a release run.
  • Volume, fullscreen, and locale survive a restart. A remapped key survives a restart (user://input_map.cfg).
  • A run saved with SaveManager.save_slot loads. Integers were cast with int(). Closing the app or backgrounding it on Android calls SaveManager.flush().
  • Credits open from the menu and show Engine.get_license_text(). GODOT_COPYRIGHT.txt and THIRD_PARTY.txt match Licenses and credits.
  • UI keys use tr() or auto-translate. You clicked through at least en and one other column from translations.csv.
  • Stretch is canvas_items / expand. A short window and a tall window keep buttons inside the safe area.
  • Keyboard, a gamepad (focus lands on a button), and touch (the on-screen buttons) can start and pause a run.
  • Package name, version, and save folder match this game, not ship-kit left over from the template copy.
  • No editor-only path, password, or keystore sits in res://.

Steam go / no-go

External resource

Steamworks labels move. Confirm the list against partner.steamgames.com (search "store checklist" and "SteamPipe"). The Godot side is only the Windows release export. Details are on the Steam page and Day 29.

  • Partner account is in good standing and the app fee for this app id is paid.
  • The build uploaded with SteamCMD is the release exe plus GODOT_COPYRIGHT.txt, not an editor binary and not a debug export.
  • Depot and branch you set live are the ones you just uploaded. Launch the build from the Steam client, not by double-clicking the exe, before you say it works.
  • Store capsules and screenshots match the sizes the partner checklist shows today.
  • Achievements you show in the store exist in Steamworks and are unlocked from the game through GodotSteam. If you have no achievements, the store does not promise any.
  • A controller can reach the menu and play the game. Steam Deck is checked against the current Deck checklist on the partner site, or you are not marking the game Deck Verified yourself.

Google Play go / no-go

External resource

Policy pages live on play.google.com/console. Search "data safety", "content rating", "closed testing", and "target API". Counts and API levels change. Godot export steps are on the Play page and Day 30.

  • The file is an .aab from a Gradle build. Export With Debug was off. Release keystore password and key password match. The keystore is backed up outside the project.
  • Play App Signing is decided (upload key versus app signing key) and you still have the upload key.
  • gradle_build/target_sdk meets the target API Play Console shows for this app today. version/code is higher than any build already uploaded.
  • Unique name is the final package name. You have not published a different game with it.
  • Data safety form matches what the game actually does. The template stores saves on device only. Ads or accounts change the form.
  • Content rating questionnaire is finished. Store listing has the icon, screenshots, and descriptions the console is asking for at their current sizes.
  • The track you are shipping to is the one you tested. A new personal account does not skip the closed test: confirm the current tester count and duration on the console (this course has been teaching 12 testers for 14 days, and that rule has changed before).
  • Billing, if you turned it on, uses the Godot Google Play Billing plugin from the official docs, with products created in the console. Ads stay off unless you accepted the ad policy on purpose.

Automatic no-go

  • Debug export, missing license text, or a crash on launch.
  • Save data lost when the Android app is paused.
  • You cannot find the keystore.
  • The store page promises a platform, language, or achievement the build does not have.

When every box you need is checked, upload. When one is not, fix that box and export again. Do not patch the store listing to hide a broken build.
