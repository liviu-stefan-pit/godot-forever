Publishing

Licenses and credits

Godot is MIT licensed. Shipping a game means the license text is somewhere the player can read it. This page is the course rule for that text, for Godot's third-party notices, and for asset credits. It follows the official "Complying with licenses" page. It is not legal advice.

What the MIT line actually requires

Not legal advice

The Godot docs say the same thing: the notes below are there so you do not ship a commercial game and forget the copyright notice. If a publisher's lawyer disagrees, the lawyer wins.

Godot's license does not force your game to be MIT. You can sell it. The requirement that does travel with the engine is the notice: the copyright lines and the permission text have to ship with the game, in a place a player can open. One of the approaches on the docs page is enough. This course uses two, because they are cheap: the credits screen, and a file next to the Windows exe.

The notice the docs print is this. Engine.get_license_text() returns the same text from the binary you exported, so it stays current when you update Godot. Prefer the method over pasting this block into a label by hand.

The docs also accept a credits screen, a licenses screen, an output log on desktop and Android, a file beside the installed program, a printed manual, or a link to godotengine.org/license in the game's documentation. The credits screen in the Ship Kit is the one you should keep. Do not delete it when you reskin a game.

Read the text from the engine

These three calls are on the Engine singleton. They read the binary, so they do not go stale when you move from one stable Godot to the next.

CallWhat you show
Engine.get_license_text()The Godot MIT notice. The credits scene assigns this to %LicenseLabel.
Engine.get_license_info()A dictionary of license name to license text for components linked into the engine.
Engine.get_copyright_info()An array of dictionaries. Each has name and parts. The credits scene lists name.

The first editor run of the credits scene writes res://licenses/GODOT_LICENSE.txt if that file is missing, using get_license_text(). Exported players cannot write res://. Create the file in the editor before you export, which that first run does.

GODOT_COPYRIGHT.txt

Godot also contains third-party libraries. Their licenses are compatible with MIT and still ask for their own copyright and license text. The engine repo keeps that list in COPYRIGHT.txt. The docs' advice for games is to ship that file, renamed so nobody confuses it with your own copyright. This course uses GODOT_COPYRIGHT.txt.

  1. Open the official page Complying with licenses. In the third-party section, follow its link to COPYRIGHT.txt in the Godot repository. The URL lives on that page so you are not guessing a path.
  2. On GitHub, use the Raw button and save the file. Steps on GitHub move. You want the file contents, not the webpage around them.
  3. Save it as C:\GodotProjects\ship-kit\licenses\GODOT_COPYRIGHT.txt. Godot will import it as a text resource. That is fine. It is also packed into the export, which covers the "inside the game" copy.
  4. For the Windows build, also copy that file next to ShipKit.exe in C:\GodotProjects\ship-kit-build\windows. The docs call this the accompanying file. Do it again after every release export, or add the copy to the same script you use for --export-release.
  5. Repeat per copied game. The file is about the engine, so the contents match across games built with the same Godot version. Refresh it when you upgrade Godot.
Why both the screen and the file

get_copyright_info() is the structured view. COPYRIGHT.txt is the document the project itself publishes. The docs recommend shipping the file because covering every dependency by hand is easy to get wrong. The credits screen satisfies the engine MIT notice. The file covers the third-party list.

Asset credits

The Ship Kit template has no third-party art, audio, or fonts. res://licenses/THIRD_PARTY.txt says that. The moment a game adds a pack, that file and the credits screen both gain a line. Free does not mean "no credit". CC0 still deserves a thanks line so you can prove what you used.

External resource

Kenney packs used later in the course are downloaded from kenney.nl/assets. Filenames inside a pack change between uploads. Pick the file by the description on the game page, and write the credit as the pack name plus "Kenney" plus the URL. Confirm the license on the pack page the day you download it. Do not invent a filename.

A credit line is one sentence a player can read. Put the same sentence in THIRD_PARTY.txt and in the credits scene, under the engine notice. Example shape, not a claim about a specific pack:

Kenney "1-Bit Pack" (the pack you actually downloaded), CC0.
https://kenney.nl/assets

Godot's icon.svg is part of the project template. You do not need a separate credit for it beyond the engine license. Fonts are the usual miss: if you drop a .ttf into assets/fonts, read its license and add a line before you export.

Before you upload

  • Credits screen shows Engine.get_license_text() and is reachable from the main menu.
  • res://licenses/GODOT_LICENSE.txt exists in the project.
  • res://licenses/GODOT_COPYRIGHT.txt is the current COPYRIGHT.txt from the Godot version you exported with.
  • The Windows folder you upload contains GODOT_COPYRIGHT.txt beside the exe.
  • THIRD_PARTY.txt lists every non-engine asset, or states that there are none.
  • No paid asset is in the project. This course stays on CC0 and engine built-ins.
